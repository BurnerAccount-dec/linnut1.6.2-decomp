# Changelog

What changed in each version of the engine, newest first. The README has the current status; the reference for script writers is in [`docs/SCRIPTING.md`](docs/SCRIPTING.md) and how to run and debug in [`docs/USAGE.md`](docs/USAGE.md).

## New in 3.1

* **Pivot arguments for the drawing functions (scaling).** `drawRect`, `drawLine2D`, `res.drawSprite`, `res.drawTexturedLine2D` and `res.drawString` take two more arguments at the end, `pivotX, pivotY` (for `drawRect` / `drawLine2D` after the render-state flag / colour, for `res.drawSprite` after the anchors; see `docs/SCRIPTING.md`). With both numbers the scale of the render state grows from that screen point, which stays where it is, instead of from the origin; if either one is `nil` or missing the function works as it always did. It only has an effect with a scale other than 1 (turning already has `setRenderState`'s own pivot).
* **Editor: Escape leaves the playtest at any time.** Esc on the level-clear / level-failed page of a level played from the editor (Shift+P) goes back to the editor, not only while the level is running (the game's own pages ignored it).
* **Editor: world gravity.** Shift+G raises the gravity of the level by 1, Ctrl+G lowers it by 1, Shift+Ctrl+G sets it back to 20 (the editor of Seasons 2.4.1 uses the same keys). The value is saved in the level as `worldGravity` and applied when the level loads in every game (before, it needed an edit of the level file). All editor keys of every game are listed in `docs/USAGE.md` ("Editor keys").
* **Seasons 2.3.0 (and the other games that use the engine's classic editor): the editor no longer stops with `attempt to get length of global 'g_camerasList'`.** The click handler of the debug cameras (Ctrl+Shift+Space) read a list that only some games define (the retail exes stop with the same error); it is skipped when the list is missing.
* **Seasons 2.3.0: the Mighty Dragon is drawn at the right size** (the sprites are scaled to the body: the dragon's circle is twice the sprite height, the tail is stretched to the body), and the Mighty Eagle of 2.0.0 is drawn larger. The eagle size is an estimate from a screenshot.
* **Seasons 2.4.1 (Piglantis): the water moves and no longer jitters.** The exe scrolls the water layers by their own `v` (pixels per second) every frame, which the engine did not do (the script never calls it), so the water stood still; the engine now scrolls them. The wobble of the water height ran on the frame counter and flickered up and down; it is now a slow smooth wave on the game's clock.
* **Retina picture sets are off by default.** For an `.ipa` with a 960x640 or 2048x1536 ("retina") picture set the engine now uses the smaller set; start with `--retina` to use the large one (`config.lua` is written again when the setting changes, `retina = false / true` is in it).
* **Seasons 2.3.0: the point pop-ups stay while the game is paused.** The score numbers and the 5K pig sprites were drawn with the in-game HUD only, so they vanished when the pause menu opened (they do in the retail game too); they are drawn above the dimmed level now.
* **Angry Birds Seasons 2.4.1 (iPhone/iPad `.ipa`, with the Piglantis episode): the water works.** The exe calls the script's global `waterUpdate()` every frame after `update()` (it applies the buoyancy and drag to every object below `objects.waterLevel` and spawns the splashes); the engine now does the same. The water itself is the theme's own foreground layers marked `water = true` (`PIGLANTIS_WATER_1` and `_2`, each with its own `v` in pixels per second and a `scaleWobbleY`): the engine draws them with their pivot on the surface line (physics y above `-objects.waterLevel`), scrolling with `v`, with the vertical wobble, over the blocks, pigs and birds (before, they were drawn at the ground as ordinary foreground, which gave a second foam band). The horizon islands (the red arch and the green islands, part of the `PIGLANTIS_PARALLAX` fixed background layers) now show: a fixed background layer without an explicit start position starts at x = 0 (before, it started where the first level's camera put it, far to the right). Compared with a recording of level 1-1 of Piglantis.
* **Angry Birds 1.0 (iPhone `.ipa`): level 1-1 now plays.** The first version keeps everything flat in one `data` folder, so it needed: the `.ipa` extractor finding that layout, no `loadlist.lua` (the game's own `gamelogic.lua` loads its sheets), fonts without the KA3D header, `createCircle` / `createBox` without a z order, sky / hills / grass built from the `BACKGROUND_n_LAYER_*` sprites for its themes (they name only `image = "BACKGROUND_n"`), `createBox` taking the HALF width and height (the exe's boxes are twice the size the table says; with full sizes the blocks hung 2.8 units above their supports and the whole tower fell by itself as soon as physics started, which also made every collision different from the retail game) and `touches` as a number (its scripts read it as the finger count, which is what lets you pick up and pull the bird). Birds launch, fly, hit and die with the feather puff. The layer speeds and scales of the backgrounds are estimates, and levels past 1-1, the sounds and the scoring of a whole level have not been compared with the retail game.
* **Angry Birds 1.0: the foreground is the right sprite, the window is the right size, and the aiming dots draw.** The foreground in front of the ground is the theme's `BACKGROUND_n_LAYER_1` (the same sprite the later versions use), for all three themes; the sky is `_LAYER_4` and the far hills `_LAYER_2`. The window of an `.ipa` game is no longer forced to the size of the picture set: its minimum size is the smaller of the config size and 1024 x 600, so the 480 x 320 game can be shrunk below its size. The first game's aiming dots are the `SMOKE_TRAIL_1..3` sprites (the later games use `TRAIL_WHITE_1..3`), which the engine did not look for.
* **Angry Birds 3.3.0 (and 2.0.0): the aiming dots draw.** Their scripts never call `addToTrajectory`: the exe records the dots itself (`addTrajectoryPositionsForBirds`), every 20 world units of flight of the flying bird and the two other birds (`recordTrajectory ~= false`). The engine now does the same whenever the script does not add dots itself; the puffs (`addPuffToTrajectory`) were already drawn.
* **Angry Birds 1.0: R in a level no longer stops with `attempt to call global 'compile'`.** The first game's scripts call a developer native `compile()` (script reload) on R; it is now defined and does nothing.
* **Angry Birds Rio 1.4.2 (Android `.apk`): the title music plays.** The apk keeps it as `ANGRY BIRDS_FINAL MASTERED.mp3.zip` (a zip holding the mp3); the extractor unpacks `.mp3.zip` files like it does `.pvr.zip` ones (unpacked folders are made again once).
* **The editor of Seasons 2.3.0 opens the game's own joint window:** J (with Shift) or F1 to F5 on two selected objects now bring up its `EditorJointPage` (joint type, motor, limits, anchors, OK/Delete) instead of creating a bare joint. The engine's editor drew the game over the page every frame (the exe-called `drawEditor` repaints the whole game), so the page is now drawn after it. Escape closes only the window (a second Escape leaves the editor). Escape in the editor goes back to the level list, not the title screen (the menu read the same key release as "back").
* **Alt, not Shift, speeds the game up:** Shift is the games' own key (zoom in the levels, the editor's shortcuts), so the double speed moved to Alt (`docs/USAGE.md` says so). In the editors, J makes a joint the way the game's version does: with the joint window where the game ships `EditorJointPage` (1.6.x and Seasons 2.x), and with the pre-1.6.0 `createJoint(name, end1, end2, type, coordType, x1, y1, x2, y2)` call (now accepted by the engine) where it does not.
* **Aiming aid, tints and ending:** `createSilhouette` now stores its pixels premultiplied by their alpha, like the sprite sheets (a see-through colour stored plain drew brighter, which is why Blue and Yellow looked washed out). The "main colour" of a sprite is the body: it only looks at the back half of the sprite (the beak is on the front side), leaves out the outline at the edge, and counts white half (a white belly or eye does not beat the body, a white bird stays white). Boomerang Bird is green now, the Black Bird black. `extra_scripts.lua` (version 10) hides the aim when the level ends or the bird is let go while held. `AB_SIL_DEBUG=1` prints the colour picked and `AB_SIL_DUMP=<folder>` saves the sprite it looked at.
* **Shift and the mouse wheel:** with Shift held the wheel zooms in steps of 5% of the normal size, as the original exe does (its wheel handler scales the step by 0.05 when its modifier flag is set), in every game.
* **The first Angry Birds .ipa (no `data_*` folder):** when a `.ipa` has no `data_iphone` / `data_ipad`, the folder that holds `scripts/gamelogic.lua` is used as the data.
* **Editor level list of Seasons 2.3.0 no longer gets stuck after an empty slot:** a slot without a level file opens a blank level (as in the game), but the game's own loader then returns early and leaves its "loading page drawn" flag set, so the next level you picked never loaded (the window still answered, nothing happened). The editor clears the flag every frame.
* **.ipa files with iPad data (Angry Birds Halloween 1.0.0):** the engine picks the `data_iphone` folder when there is one, otherwise the iPad one, and builds `config.lua` from the picture size the data has (480x320, 960x640, 1024x768 ...); iPad-sized data runs as `deviceModel = "ipad"`, which is what makes the scripts ask for `images/1024x768` and `fonts/1024x768` instead of 480x320. The log says "ipa:" for an .ipa. Games unpacked by an older build are unpacked again once.

## New in 3.0

* **Angry Birds 3.3.0 (Android) runs**, including Red's Mighty Feathers. Page 1 is the 15 classic levels (their own game mode), page 2 the 15 Egg Defender levels (eggs, nests, pigs with gadgets). New for this: PVR v3 textures (RGBA 4444/8888, RGB 565, ETC1), particles stored one file per effect (`scripts/particles`), the Rovio ad and channel services answered with "nothing available", the natives the 3.x scripts call (`getLocale`, `isEditing`, `setRollingSound`, `setRovioShelfAllowed`, `setOffsetedViewport`, `setChannelCountLimit`, `printWarning`, `releaseFont`, `releaseAudio`), `setSensor`, `setFilterMask` and `setFilterCategory` (the collision filter between objects: each side's mask must accept the other's category), `createPolygon` with a list of points (`{x=, y=}` entries) instead of a width and height, the touch-device slingshot band (`drawRubberband`), `blockCollision(name, other, force, damage)` with a number as the last argument, `getFirstOf`, `getGameTimer`, `getSpeed`, `drawLine`, a predicted flight for `getTrajectory` (the Egg Defender cannons aim with it), and a block that is removed now takes its joints out of `objects.joints` in the 3.x games too (the Egg Defender scripts followed them to a block that was gone).
* The star particles of 3.x games now spread out instead of dropping straight down: those particle files keep their speeds and angles in an `emitter_circle` / `emitter_box` table, which the engine did not read. `getTimeDifferenceInSeconds` (called when the game comes back from the background) is defined.
* Red's Mighty Feathers objects work: the 3.x forces queued by `applyForce` run before every physics step (Red's anti-gravity flight, thrusters), `applyImpulse`/`applyForce` accept the optional application point (the bubble gun's bubbles now launch), and objects flagged with `setObjectParameter(name, 8, 1)` get their per-step forces: `forceX`/`forceY`, `forceRelative` up to `targetVelocity`, `airResistance`, `frictionXRelative`/`YRelative` and `floatability` (bubbles float instead of dropping, propellers/fans push). The `gameResumed` crash when the window is clicked is fixed.
* **Angry Birds Seasons 2.3.0 (Android `.apk`) plays:** I went through every function its scripts call; the ad checks `isExpandableAdReady`, `isVideoAdReady` and the like answer false, and `checkMainMenuAd` does nothing. Menus, the Seasons 2012 episodes and Cherry Blossom level 1 with its tutorials run without script errors.
* Aiming aid: the silhouettes are 35% see-through and, in every game except Space and Star Wars, drawn over the birds and pigs (the engine draws the aiming dots after the characters). `isInterstitialAdReady` and the other ad-ready checks answer false (Seasons 2.3.0 stopped on it after the first level loaded).
* **1.3.5 Golden Egg levels (and the other levels with joints) load:** `createJoint` also takes the joint system before 1.6.0, `createJoint(name, end1, end2, type, coordType, x1, y1, x2, y2)` with the values in a row instead of one table (the old levels still make their tires and links this way). The aiming aid of `extra_scripts.lua` (now version 10) is a row of small silhouettes of the selected bird's current sprite in its main colour; the old dots are commented out in the script. `createSilhouette` takes a negative red to use the main colour of the source sprite. A `MedioEvents` stand-in (every call does nothing) is defined in every game for the Seasons 2.x analytics (Seasons 2.3.0 stopped at its first update without it).
* **Extra scripts with an .apk / .ipa:** `.lua` files named on the command line (dragged onto the exe next to the `.apk`, `.ipa` or game) are loaded once the game scripts are up, each in its own protected call (a script that is not made for the game prints `extra script error:` and the game goes on). `extra_scripts.lua` (now version 8; the aiming dots fall back to the flower trail `TRAIL_FLOWER_2` when the game has no Space or Star Wars dot) works with Angry Birds 1.3.5 and the Angry Birds Free 1.0.0 `.ipa`: those scripts keep the rubber-band limit in `shootMaxLength` instead of the function `rubberBandMaximumLength()`, so the aiming aid used to stay off.
* 3.x natives for Red's Mighty Feathers added: `setFriction`, `setDensity`, `resizeCircle` (the pufferfish-style blocks), `setVisible`, and `inheritTeleportation` (a no-op, it only matters for portals). Blue Bird's split no longer stops the update loop with an error. Bird powers checked on original and Mighty Feathers levels: Red, Yellow, Blue, Black and Boomerang respond to a click.
* A script error in a 3.x game no longer ends the game: it is printed once ("script error (skipped, the game goes on)") and the frame carries on. `AB_MISSING=1` prints the globals a game's scripts read that nothing defines, and `--cmd-at <frame> "<command>"` runs a console command at a given frame (for tests).
* **Android .apk and iPhone .ipa files open directly.** Drag an `.apk` or `.ipa` onto `AngryBirdsEngine.exe` (or use "Open with", or give it as an argument: `AngryBirdsEngine.exe AngryBirds_1.3.5.apk`). The engine unpacks the game's data once into `%LOCALAPPDATA%\AngryBirdsEngine\apk\<name>` (an .apk's `assets/data`, an .ipa's `Payload/<name>.app/data_iphone`; textures kept as `.pvr.zip` are unpacked too), writes a `config.lua` there (an .apk: window 800x480, `deviceModel = "android"`; an .ipa: window 480x320, `deviceModel = "iphone"`, and `isLiteVersion = true` for the Lite game, whose pictures are in `images/480x320_lite`; edit it if you like) and runs the game from that folder.
* New readers for this: a zip reader, ETC1 textures (the Android sky and ground sheets), PVRTC 4 bits per pixel textures (the iPhone sky sheets) and the older text file layout of the Android builds. Static blocks (ground, rock) use tiling textures the scripts name as `.png`; when the .png is missing the `.pvr` is used.
* A level the scripts ask for in the wrong level folder (the editor looks for the Lite levels in `levels/pack1`, the iPhone Lite game keeps them in `levels/packLite`) is looked for in the other level folders, so the editor opens them instead of crashing.
* The sound of a video is mixed down to mono when the game mixes in mono (the iPhone game: 16000 Hz mono); before, a stereo clip played at half speed and an octave low. The sound of a video is decoded exactly as 16 bit stereo 44100 Hz (float and 8 bit output is converted) and its length is checked against the reader's own timing; the console prints a `video sound:` line with what the decoder gave. It is also fitted to the length of the picture when the decoder reports a sample rate or channel count that does not match it (it played too slowly).
* The save folder (`%APPDATA%\Rovio\<product>`, for an .apk or .ipa `Angry Birds (<file name>)`) is created when missing, so settings and high scores are written (before: `saveLuaFile: cannot write`).
* Checked with Angry Birds 1.3.5, 2.1.0 and Angry Birds Free 1.0.0 for iPhone (main menu, episode and level select, level 1 with the tutorial, the tutorial closed). 2.1.0 also needed `isHDVersion` to be a plain false value (it picks the 1280x800 sheets otherwise), the debug editor to stay off when its script is missing, an empty `nuked` table, and `particles.clear()`, which scripts call when a tutorial closes (`particles.clear("menu")` removes the menu particles only, so a level's confetti keeps drawing).

## New in 2.9

**This release contains everything since the 2.8 release candidate, which was never published: the Star Wars physics port, the Seasons 4.1.0 start-up fix and the first `engine` table (all described below under "Angry Birds Star Wars" and the first Lua entries) as well as the later additions.** The new Lua features of 2.9, in one list:

* `tuning` table (about 40 built-in numbers: Star Wars damage, wobble and water, Rio wobble, Classic damage, solver iterations and sleep, zoom, particles, gravity) and `engine.tuningDefaults`.
* Rule hooks: `engine.shouldCollide(a, b)`, `engine.strengthChange(name, other, old, new)`, `engine.drawObject(name)`.
* Events: `update`, `levelLoaded`, `objectCreated`, `objectRemoved`, `contact`, `drawBackground`, `drawForeground`, `drawBackgroundBefore`, `drawForegroundBefore`, `drawGameBefore`, `drawGame`.
* Theme layers as data: `getThemeLayers`, `setThemeLayer` (`dx`, `dy`, `hidden`, `speed`, `scale`, `sprite`, ...), `getCamera`, `tuning["background.skip"]` / `["foreground.skip"]`.
* `clearParticleCache()` is real now: edit `particleTable.particles[name]` and call it, and new particles use the edited definition.
* The Classic ground strip as layer list 2 (`getThemeLayers(2)`), and the events `physicsStep`, `physicsStepEnd`, `contactEnd`.
* `engine.damage(attacker, victim, force, damage)` replaces the damage of a hit; `getGroundColor()` / `setGroundColor(r, g, b)` for the ground fill of the old-style foreground.
* `engine.particle(type, t)` edits or drops every new particle; `solver.velocityThreshold` and `solver.maxLinearCorrection` open two more Box2D numbers (both Box2D copies).
* `solver.baumgarte`, `solver.maxRotation` and `solver.angularSleepTolerance` open three more Box2D numbers (both Box2D copies).
* `engine.force(a, b, mx, my, force)` replaces the force of any contact (all games).
* `engine.drawSprite(sprite, object, x, y)` is called for every sprite drawn: return false to skip it or a table (dx, dy, angle, sx, sy, alpha, r, g, b, blend, effect, ...) to change how it is drawn.
* Star Wars block against block damage now goes through `engine.force`, `engine.damage` and `engine.strengthChange` like bird against block.
* Checked with real hits: engine.damage, engine.strengthChange and engine.force fire on Star Wars block collisions; engine.drawSprite checked on Star Wars, Rio and Seasons.
* Checked with one smoke script on Classic, 2.0.0, Space, Star Wars and Rio (Seasons not run). `docs/SCRIPTING.md` has the table of what was checked and a map of where each part of the engine can be changed from Lua, including the Lua tables that are plain data.
* A complete native function reference and a modding guide with pseudocode in `docs/SCRIPTING.md`.


**Angry Birds Star Wars: the engine now follows the retail exe's physics and per-frame update.** Everything below is ported from the decompiled `AngryBirdsStarWars.exe` (addresses in brackets); the modding side of it is in [`docs/SCRIPTING.md`](docs/SCRIPTING.md#angry-birds-star-wars).

* **Contact filter and object flags (0x410e70).** Star Wars has its own rule for which two objects collide: collision groups (`setCollisionGroupIndex`, parameter 36), per-object material lists, kind 7 objects that never collide with each other and parameter 19 as the exception. The natives that set one flag of an object record (`setBlockCollisionEnabled`, `setIgnoresScore`, `setKeepOrientation`, `setAffectedByForceMultipliers`, `setIsWater`, `setWaterDensity`, `setControlled`, `setTimeSinceCollision`) are real now, not no-ops.
* **Water (0x41e440, 0x423270).** A gravity sensor flagged with `setIsWater` is a pool: boxes push up and circles pull towards their centre with a force that fades over the top 1.5 world units, with extra drag for birds (`setBirdWaterDrag`, 0.4) and objects (`setObjectWaterDrag`, 0) and a force multiplier for fresh birds (`setWaterForceMultiplier`, 2).
* **Collision damage (0x42f9d0).** Star Wars no longer runs the older games' damage rules. Forces divide by 10 after the config's `forceDamageMultiplier` (1); a bird hitting a block uses the momentum difference of the two (bird scaled by its damage multiplier and `powerupDamageMultiplier`), a HOMING bird that has not collided yet does a fifth of the damage, a block that dies takes the bird's velocity (at once with `useLegacyCollisionPath`, after the step otherwise) and the contact is switched off; two blocks take `force * factor - defence` (strength drops by the floor of it), `ignoresScore` objects score nothing, and the score added is `floor(damage) * scoreDamageMultiplier` followed by `addScoreToBird`. Damaging sensors (kinds 5, 6 and 7, unless the other object has parameter 20) hurt blocks with their definition's `damage`. `birdCollision` now receives `(a, b, force, damage, pointX, pointY, normalX, normalY)` and `blockCollision` `(a, b, force, wasDamageDone, false, damage, pointX, pointY, normalX, normalY)`, which the scripts' damage particles and collision actions read (they used to get nil). The first collision of a bird starts its gravity timer.
* **Hit wobble (0x42fe61).** Blocks with a `bounceAmplitudeMultiplier` (parameters 6 and 7) wobble when hit: the amplitude is `min(force * 0.02, 0.1)` and the phase of each object is shifted by its place in name order times a quarter turn. Two birds that collide start the same wobble unless an object has parameter 11 set.
* **End of contact and kill timers (0x41f370, 0x433464, 0x433771).** When a contact ends both bodies are woken, `exitTriggerCollision` fires for sensors (the sensor bookkeeping runs its exit side) and `exitCollision` always fires. A kind 4 sensor touched by a non-sensor, and an object with `stopOnExit` (parameter 34) leaving a flagged sensor, get a kill timer that the frame update counts down and then destroys the object. Sensors of kind 5 and 7 that drift beyond 0.88 times a level limit are removed straight away.
* **Per-frame object sync (0x433500).** `hasMovingObjects` ignores joints and any object with parameter 12 set and tests the absolute spin; `hasMovingObjectsZeroTolerance` is published (anything but a controlled object that moves at all); every awake object gets `objects.world[name].velocity` (the speed), which the scripts' specialty speed limit and drag threshold read; objects with the material `propeller` (and any object after `setRecordVelocity`) publish `xVel`, `yVel` and `angle` like birds do. Objects with parameter 9 (enable flipping) turn to face their direction of travel by calling parameter 8 each time they move faster than 3 sideways.
* **`createLineShape` (0x439640).** A body made of edge shapes, one for each pair of neighbouring vertices from `clearVertices` / `addVertex`, with the same arguments as `createPolygon` (Box2D 2.2 builds). The world entry has `type = "line"`. The retail game only uses it for the editor's `STREAM_1` block, but mods can use it for thin, one-sided or open terrain.
* **Aiming aid.** `populateAimingAid` (0x402770) lays the dots out along the stored trajectory, as the Space one does; the trajectory itself still comes from `updateBirdTrajectoryTable`.
* **`renderGravityVisualsNative` (0x415f90)** is implemented: circle sensors draw each entry of their `gravityVisuals` list eight times around the sensor and box sensors draw bars along their length. The game's own script calls it with three arguments, the exe reads the missing fourth (the zoom) as 0, and the retail game therefore draws nothing; the same happens here. A mod that passes the zoom as fourth argument gets the rings.
* **Level joints keep their fields.** `createJoint` stored only the values it used on `objects.joints[name]`, so a level-select scene (Endor, Death Star 2) lost `isDrawn`, `breakable`, `breakForce`, `jointPosX` and `jointPosY`; the retail scripts read them to draw vines and ropes (`gamescene.lua`) and to decide which joints break. They are kept now. `AB_JOINTDBG` also logs how many entries each `createJoints` call got, and `AB_DUMPLEVEL=<prefix>` writes one file per loaded level (`<prefix>.<level>.lua`).
* **Star Wars foreground layers (0x44b9xx).** With `NEW_THEME_SYSTEM_FOREGROUND` the theme's `fgLayers` only go through the new-system routine; the old positional/named foreground loop used to run as well, so Cloud City's foreground was drawn twice. Without the flag only the positional loop runs, and its fourth entry (scale) defaults to 1, not 1.5.
* **Stale joints after a tap.** `removeObject` clears `objects.joints` entries of the removed object in Space and Star Wars too (tapping a log or pig in a level select no longer leaves a joint pointing at a missing object, which stopped the draw loop before the buttons and cursor).
- **Angry Birds Seasons 4.1.0 start-up.** The scripts read the globals `uniqueInstallationId` (settingsWrapper.lua) and the table `native` (createStartUpAssets); both exist now (as bare globals and in `_G`, the real global table, which is where createStartUpAssets looks: `_G.native`), so the game no longer stops with "attempt to concatenate global 'uniqueInstallationId'" / "attempt to index field 'native'".
- **Seasons 4.x start-up (2).** The scripts call `requireFile("Scaling.lua")` and similar, both as `_G.requireFile(...)` and by bare name; the engine now has it (runs the file once, looked up in the game's script folder and then `commonScriptPath`). A Seasons build whose config has `commonScriptPath` is no longer treated as Star Wars / Space (no Star Wars physics, no Space natives): it runs `scripts_common/gamelogic.lua` and the rest of the Seasons start-up as a Seasons game.
- **Backgrounds and foregrounds from Lua.** `getCamera()`, `getThemeLayers()` and `setThemeLayer(index, fields)` give the theme layers as data (`dx` and `dy` move a layer in screen pixels, `hidden`, `speed`, `scale`, `sprite`, `offX`, `offY` and more), `engine.on("drawBackground" / "drawForeground")` (and the `...Before` versions) let a script draw its own layers, and `tuning["background.skip"]` / `tuning["foreground.skip"]` replace the engine's drawing entirely. `docs/SCRIPTING.md` has recipes for sine-wave parallax.
- **Rule hooks.** `engine.shouldCollide(a, b)` lets Lua decide whether two objects collide (every game), and `engine.strengthChange(name, other, old, new)` lets Lua replace the strength a block is left with after a hit. `engine.tuningDefaults` lists every `tuning` name with its default.
- **Drawing and damage hooks.** `engine.drawObject(name)` can stop one object being drawn, `engine.on("drawGameBefore" / "drawGame")` draw behind and over the scene, and four `classic.*` tuning names open the damage rules of the older games.
- **Particle tuning.** `particle.amountScale`, `speedScale`, `lifeScale`, `sizeScale` and `gravityScale`; `clearParticleCache()` re-reads the particle table.
- **Everything changeable from Lua.** New global `engine` table: `engine.original` / `engine.resOriginal` (the engine's own natives, kept when a script replaces a global), `engine.natives()`, and `engine.on` / `off` / `emit` with the events `update`, `levelLoaded`, `objectCreated` and `objectRemoved`. `docs/SCRIPTING.md` has a new, complete native function reference and a chapter "Changing the engine from Lua".
- **`tuning` table and `contact` event.** The engine's built-in constants can be set from Lua (`tuning["sw.forceDivisor"] = 5`): Star Wars damage divisor, homing damage, hit wobble and sensor removal limit, Rio wobble, and the mouse-wheel zoom step and duration; and, in every game, the Box2D solver (iterations, slop, sleep time and tolerance), the Star Wars water formula, the revert-gravity strength, the hit-wobble curve, the flip speed and the `hasMovingObjects` thresholds. `engine.on("contact", function(a, b) ... end)` fires when two objects begin to touch. `docs/SCRIPTING.md` ends with a modding guide with pseudocode and recipes.

## New in 2.2.3

**Reading and changing the z of objects.** Everything about the `z_order` of blocks can now be asked for and changed from the scripts and the console (the rules of the draw order are under "Draw order and z"):

| Call | Meaning |
|---|---|
| `getObjectZOrder(name)` | the object's current `z_order`; `nil` if there is no such object (before: -1e9) |
| `objects.world[name].z_order` | the same value, from the table the scripts already read. It is kept up to date: `setObjectZOrder`, `bringObjectToFront`, `sendObjectToBack` and the console commands below write the new value into it |
| `setObjectZOrder(name, z)` | sets it (as before; now also updates `objects.world`) |
| `bringObjectToFront(name)` | puts the object in front of every other one and returns its new `z_order` (the highest z in the world plus 1, at least 5, so it is in the group that is drawn last in every game); `nil` if there is no such object |
| `sendObjectToBack(name)` | puts it behind every other object of its group (the lowest z in the world minus 1) and returns the new `z_order`. The static blocks below z 5 are drawn first whatever z the others have, so a moving block cannot go behind those |
| `getObjectDrawOrder()` | a table of object names from the back to the front, in the order `drawGameNative` draws them (the trajectory dots are not objects and are not listed) |
| `getRenderZ()` | the `z` of the current render state (`setRenderZ(z)`, which already existed, changes only that value) |

Console: `zorder` lists every object back to front with its `z_order`; `zorder <name>` shows one and where it is drawn; `zorder <name> <z>` sets it; `zfront <name>` and `zback <name>` bring it to the front or send it to the back. For example `zorder BLOCK_WOOD_3 20`.

## New in 2.2

**Video.** `playVideo(videoPath .. "/" .. name)` plays an MP4 / M4V inside the engine window, no other program. Click, Space, Return or Escape skip it; the Lua call returns when it ends. `videoPath` is a Lua global filled from `config.lua` (`videoPath = "videos"`), so it can be read and changed from the scripts. `stopVideo()` and `isVideoPlaying()` also exist. The sound track needs AAC decoding, which is done through Windows Media Foundation (Windows only; without it the picture plays silently). Decoder: h264bsd (`third_party/h264bsd`, own licence).

**`setRenderState(tx, ty, sx, sy, angle, pivotX, pivotY, alpha, skewX, skewY, bendX, bendY, z [, bendFunction])`.** Arguments 9 to 17 are new and optional (15 to 17 are the tint, see below).

| Argument | Meaning |
|---|---|
| `skewX`, `skewY` | shear about the pivot (units: shift per unit of height / width), applied before the rotation |
| `bendX`, `bendY` | how far the middle of the sprite is pushed sideways / up, in pixels; drawn as an 8x8 grid |
| `z` | draw order of the sprite (and of `drawRect` / `drawLine2D`) against the game's blocks and other sprites that use `z`; 0 means "in the order the script drew it". The same scale as a block's `z_order`. See "Draw order and z" |
| `bendFunction` | optional Lua function `f(t, 0, 1, 1)` with the same arguments as the gamelogic tweens (`tweenLinear(currentTime, startValue, changeOfValue, duration)`); it is sampled 9 times and its curve shapes the bend. Without it the bend is an arch (sine) |

`setObjectZOrder(name, z)` / `getObjectZOrder(name)` set the draw order of one block (Rio's own `zOrder` still works; in other games a group with a z-ordered object is sorted by it). Both kinds of z are on one scale, see "Draw order and z". The debug overlays drawn by `drawRect` and `drawLine` (the 8 key) now rotate with the body.

**Speed.** `physicsSpeedFactor` (Lua global) now changes only the physics step rate; the scripts' `update(dt)` is untouched. `gameSpeedFactor` multiplies the time step of everything (physics, scripts, animation). Both are read every frame, so `gameSpeedFactor = 0.5` in a script or `set gameSpeedFactor 0.5` in the console works. Defaults 1.

**Frame rate.** The window now runs without waiting for the monitor (vsync off) and without a cap, so on a fast machine it renders far above 60 fps. `fps 120` caps it, `fps 0` removes the cap, `vsync on` waits for the monitor. Start options: `--fps N`, `--vsync`.

**Audio.** From the console or Lua (`res.` functions): `audiospeed [x [track]]` / `res.setAudioSpeed(x)` change playback speed (pitch follows), `audiopause` / `audioresume [track]`, `mastervolume [v]`, and `res.setAudioClipVolume`, `res.setAudioClipSpeed`, `res.getAudioSpeed`, `res.isAudioPaused`, `res.getMasterVolume`. At speed 1 the mixer path is unchanged.

**Startup commands.** `--cmd "<console line>"` (repeatable), `--startup <file>` (one console line per file line) and `--prompt` (or `AB_PROMPT=1`: an `ab>` prompt before the game opens, an empty line starts it) run console commands before the first frame.

**Console.** New: `fps`, `vsync`, `gamespeed [x]`, `physicsspeed [x]`, `set <name> <value>` / `get <name>` (any Lua global), `audiospeed`, `audiopause`, `audioresume`, `mastervolume`.

**Editor.** Saving a level into a folder that does not exist now creates the folder; an absolute path is used as it is.

**Tint (`setRenderState`, arguments 15 to 17, and dedicated functions).** Sprites can be multiplied by a colour: red, green, blue from 0 (none) to 1 (unchanged); above 1 brightens. Like alpha it affects what is drawn after it and is reset when the engine starts a new drawing pass, so set it right before the sprites you want tinted.

    setRenderState(0, 0, 1, 1, 0, 0, 0, 1, 0, 0, 0, 0, 0, nil, 1, 0.3, 0.3)   -- ..., z, bendFunction (nil), tintR, tintG, tintB: reddish
    _G.res.drawSprite("BIRD_RED_YELL", 200, 250)

The single values also have their own functions, so you do not have to repeat the others:

| Function | Effect |
|---|---|
| `setTint(r, g, b)` / `setTint(grey)` | tint of what is drawn next, for example `setTint(0, 1, 0)` |
| `getTint()` | returns r, g, b |
| `resetTint()` | back to 1, 1, 1 |
| `setAlpha(a)` | transparency, 0 to 1 |
| `setSkew(x, y)` | shear (arguments 9, 10) |
| `setBend(x, y)` | bend (arguments 11, 12) |
| `setRenderZ(z)` / `getRenderZ()` | the z of the render state alone (argument 13 of `setRenderState`), see "Draw order and z" |
| `setBlur(pixels)` / `resetBlur()` | sprites are smeared over this many pixels (nine copies, each with 1/n of the alpha; `setRenderState` argument 18); 0 is sharp |
| `setPixelate(size)` / `resetPixelate()` | sprites are drawn in blocks of size x size sprite pixels, at most 64 x 64 blocks (`setRenderState` argument 19); 0 is off |

Example: a faded green bird, then the next sprite normal again:

    setAlpha(0.5) setTint(0, 1, 0)
    _G.res.drawSprite("BIRD_RED_YELL", 300, 250)
    setAlpha(1) resetTint()

**Editor, TAB.** TAB in the editor saves a copy of the level and starts the physics; the second TAB loads that copy back. The copy is now also kept in memory, so it is found even when the game folder cannot be written (for example under Program Files).

**Level start.** Every level load starts a new physics world, and blocks are created asleep; see the debug line below for the switches.

**`dec` folder.** `--decrypt` now also decompiles bytecode (1.6.3.1, 2.0.0, Seasons, Rio) into plain Lua with `java -jar unluac.jar` (Java must be installed; `tools\unluac.jar` and `tools\unluac-alt.jar` ship with the engine, `AB_UNLUAC=<jar>` picks another). Every result is checked by loading it as Lua 5.1 and only files that load are written; a list of the files that could not be decompiled is printed (Rio: `gamelogic.lua`, `menu.lua`, `page.lua` and a few menu files are too large for the jars and stay in the game's own bytecode, `--use-dec` falls back to them). `AB_DEC_KEEP=1` keeps the `.luac`. unluac: see its own licence.

**Hatchery and Challenges in 2.0.0 (debug build).** When the debug keys are on (the default; `AB_NODEBUGKEYS=1` turns them off) and the Angry Birds Island HD scripts are in the game's data folder (`data\\hatchery\\` with `hatchery.lua`, and `data\\scripts\\challenges\\challenges.lua` + `ChallengePage.lua`, ; the two ui components the Hatchery needs, CompoImage and InvisibleButton, are built into the engine), the engine switches `g_hatcheryEnabled` / `g_challengesEnabled` on after `options.lua` loads and adds HATCHERY and CHALLENGES buttons next to EDITOR on the main menu. `hatchery.lua` runs with `this` set to its own table, as its other files expect. Hatchery's isometric map and objects are drawn by `src/lua/hatchery_natives.lua` (the tile manager natives: animations run in seconds and turn about their own anchors, placement is checked against water, cliffs and solid objects, an egg needs an empty nest, eggs and birds are drawn inside their nest). The egg painter's canvas, the painted egg sprites (`EGG_PAINTED_n.png` in the user data) and the saved world (`tileMapSave.lua`, `savedEggSprites.lua`) are natives of the engine. The shop log is centred on the screen. The Hatchery needs the full HATCHERY image, font and audio folders. In a level (debug build) an egg button after the pause and restart buttons drops the Hatchery's bird bench; a bird picked from it replaces the next bird of the level (`setupCompoObject`: the object is drawn from the bird's sprites, each with its own offset, scale and angle) and the Mighty Eagle button on the bench calls the level's eagle. The iPad's `MENU_BUTTON_HATCHERY` sprite is not in the data, so the button is the egg sprite on a shadow.

**Debug.** `AB_BODYDUMP=n` also prints, once, gravity, the physics library, every body's mass / damping (`BI`) and the static bodies (`BS`). `AB_DMGDBG=1` lists every damaging contact. A revolute or prismatic joint that has both a motor and limits now reverses at its limits by itself (the Classic scripts never call `checkJointLimits`, which is why the Golden Eggs pickaxes in GE_21 used to sit still). Rio physics follows the retail exe's own solver (see the Rio notes below): 10 velocity and 10 position iterations, the full polygon skin in the position solver (`AB_SOLVERSKIN` can still override it for testing), and Box2D 2.1-style revolute and prismatic joints. Every level now loads into a brand new physics world, and the blocks are created awake. Before, a restarted level settled differently from the first load, which made Ham 'em High 12-1 and 12-8 (P5_610, P5_628) cave in and kill pigs on some restarts; in the sandbox both now give 0 damage events on the first load and on six restarts in a row, but retail has not been compared. `AB_KEEPWORLD=1` restores the old shared world, `AB_WAKEDBG=1` prints each time a script wakes a body. Classic now uses the exe's own continuous collision step (compared with the decompiled exe and the retail game on GE_21). The retail exe runs Box2D 2.1.0, whose time-of-impact pass finds the earliest impact of all contacts that involve a static body, moves the bodies there, solves the touching island with the rest of the step and repeats; the Box2D copy used for Classic had the later per body version, which threw the overlapping hidden TNT blocks of GE_21 (welded to a far static block) and the pigs on them around, destroyed about 20 pigs and scored 138030 before any input, where retail settles the pigs in the pit at 110. Blocks are also created awake again, as in the exe (an earlier v2.2 build started them asleep, which made objects stand still that should move). `AB_OLDTOI=1` switches the time of impact routine back to the bundled Box2D one (the default is the exe's own, ported from 0x4e70d0). `AB_ASLEEPSTART=1` starts blocks asleep for testing and `AB_NOCCD=1` turns continuous collision off. The regular island solve, the position solver's equalized mass and the TOI island follow the exe too. The hand cursor (`CURSOR_*` sprites) is always drawn last, on top and unaffected by z, blur or pixelation, and an editor whose scripts draw no cursor (2.0.0) shows the system cursor. Leaving a level played from the editor through the pause button now returns to the editor (it crashed in `updateMenuPage`).

## Changes since 2.1

Everything below was added after the 2.1 release and is part of 2.2. It is grouped by what it touches; the physics work is a comparison of the engine's functions with the Ghidra decompile of each retail exe.


### Lua compiler fix (constants beyond 256)
In a function with more than 256 constants, an expression such as `x + 800 * t.dir.x` was compiled so that the constant's register was overwritten by the second operand, giving `x + t.dir.x * t.dir.x`. The compiler now evaluates the second operand first (the same order later Lua versions use), for arithmetic and comparisons. Large scripts, such as a long game-logic file, now calculate these expressions correctly.

### Physics: Angry Birds 1.6.2 and the other Box2D 2.1 games (Classic, Seasons)

- Continuous collision follows the exe's own routine (the time of impact pass ported from 0x4e70d0): the earliest impact of all contacts that involve a static body is found, the bodies are moved there, the touching island is solved with the rest of the step and the pass repeats. `AB_OLDTOI=1` brings back the bundled Box2D routine, `AB_NOCCD=1` turns continuous collision off.
- `b2Contact::Update` checks the overlap of the two fixtures' boxes before it runs the narrow phase, as the exe does; the wake-up rules of `b2Body` and the term order of `Solve33` in `b2Math` match the exe.
- The island solver, the position solver's equalised mass and the TOI island follow the exe. Blocks are created awake, and every level load starts a brand new physics world (`AB_KEEPWORLD=1` restores the shared world). A restarted level now settles like the first load.
- Revolute and prismatic joints with both a motor and limits reverse at their limits by themselves (the Classic scripts never call `checkJointLimits`), which makes the Golden Eggs pickaxes move.
- The Eagle can be used once per level, as in the retail game.
- Seasons 1.0.0 to 2.2.0 use the same Box2D code as 1.6.2; the exes differ only in compiler inlining, so no separate physics is needed.

### Physics: Angry Birds Rio 1.4.2

Rio's exe contains a Box2D 2.2.0 trunk build with its own time of impact solver, which the engine now follows:

- `Island::SolveTOI` works on the earliest-impact contact, advances each body's sweep, and the "leap of faith" that commits the new positions applies to **every** body of the island, not only the two bodies of the contact.
- The group of bodies of a time of impact island stops growing at 32 bodies (`b2_maxTOIContacts`), the contact list has room for 4 times that.
- Contact partition, the sleep condition (it no longer depends on whether the position solver finished), the position solver's mass normalisation, its -1.5 x linear slop threshold and the TOI position solver (which moves both bodies) match the exe. Constants: linear slop 0.05, TOI target 0.15, tolerance 0.0125, 20 position iterations, Baumgarte 0.75.
- Rio instruction matching (v2.2): the position solver subtracts both radii in full (`b2_solverSkinFraction` = 1), the circle manifold returns the normal (1, 0) for coinciding centres, revolute and prismatic joints use the exe's 2.1-style Init / SolveVelocity / SolvePosition (including the large-detachment step), `b2Mat33::Solve33` uses the exe's term order, `b2Body::SetType` / `ResetMassData`, `AddPair` (no waking) and `Collide` (awake test) follow the exe, and the world is stepped with 10/10 iterations. Smuggler's Plane 1-10 still holds and 12-15 stays stable.

### Physics: how closely it follows the exes

The Box2D code of each game was compared, function by function, with the Ghidra decompile of that game's exe:

- **Angry Birds Rio 1.4.2** (`AngryBirdsRio.exe`, Box2D 2.2.0 trunk with 2.1-style joints): every Box2D function the engine uses was compared and made to follow the exe, including the order of the floating point terms. That covers the world step and solve, the time of impact pass, the contact manager (AddPair, Collide), the contact and position solvers and the polygon / circle manifolds, the island solve, the revolute, prismatic, weld and distance joints, bodies (SetType, mass data), the shapes' mass, centroid and ray casts, the GJK distance routine, and the dynamic tree and broadphase (the exe has the older 2.2.0 tree with a rebalance pass after each pair update, which decides the order contacts are created in).
- **Angry Birds 1.6.2** (Box2D 2.1.0): the world, the time of impact pass, the island and contact solvers, the joints and the collision functions follow the exe.
- **Angry Birds 2.0.0**: its decompile was compared with the 1.6.2 one. Of the Box2D functions, all but a few dozen are identical after the names are stripped, and the rest differ only in addresses, so 2.0.0 runs the same physics as 1.6.2.

What cannot be matched is the last bit of `sin`, `cos` and `sqrt`: the exes call the x87 versions, the engine uses the host's math library. Apart from that the physics in these games is the exes' physics. This was done by reading the decompiled code, not by comparing with recordings of the retail games, so a mistake in a function the engine does not run (or in a case no level reaches) would not have shown up.

### Drawing and speed

- **Static blocks that tile a texture draw correctly again.** A file used both as a sprite sheet image and as a repeating block texture is now kept as two textures (one that repeats, one that does not). When both wanted the same file, terrain showed as one flat colour.
- **Textures are uploaded when the sprite sheet is created**, behind the loading screen, like the exe does, instead of on the first draw. The frames after a menu or a level opened used to stutter, the more so the more sheets a game has.
- **A sprite name that is in no sheet is remembered**, like one that is. Before, every `drawSprite`, `getSpriteBounds` or `getSpritePivot` call with a name that does not exist walked every sprite of every sheet (about 40 microseconds in Rio, per call); scripts that measure or draw such names for each object each frame lost many milliseconds per frame. Composite sprite lookups are remembered too (a missing name now costs about 2.5 microseconds).
- **The hand cursor** (`CURSOR_*`) is now drawn at the very end of the frame, on top of everything the scripts and the engine draw (a background, a panel or the game drawn after the script's cursor call used to cover it, as in the Seasons editor), with the clip rectangle off and with z, blur, pixelation, transparency and tint of the sprites before it taken away. The system cursor is only hidden when a cursor sprite was really drawn that frame.

### Angry Birds Space (PC)

Space's menus and levels load, draw and play: the level is built by the scripts, the planets pull the birds and blocks (gravitation sensors, Box2D 2.2.0 like Rio and no world gravity), the slingshot launches the bird and the aiming aid draws its dots. Only the first theme's levels were tested. Still approximate: the background layers (positions and parallax), the aiming aid (it flies the bird on alone under the sensors and ignores what it would hit), the foreground, and the compound bodies, particle scale and several shader and font natives, which are provided but not tested against a level that uses them.

- Space's scripts are AES encrypted with their own key, which the engine knows; they are read from `scripts_common` as well as `scripts` (`config.lua`'s `commonScriptPath`).
- The natives Space's `gamelogic.lua` expects at start that the other games do not have (bitwise or, vector helpers, device id, time differences, Flurry and logging calls, timers) are provided by a built-in Lua file, `space_natives.lua`.

See "New in 2.2" above for video, `setRenderState` extensions, tint, console commands, speed controls, the frame limiter and the `dec` folder.

## Fixes after the 2.4 notes

- **Space aiming aid** now follows the retail AimingAid (0x45dd00/0x45dea0/0x45dfd0/0x45d570): dots are born every `simulationAimSpawnTime`, travel along a Catmull-Rom spline of the trajectory at `simulationAimSpeed` points per second, shrink from 1.2x to 0.2x and vanish at the end of the path.
- **Space natives checked against the exe**: `renderGravityVisualsNative` (0x46a5d0) is called by the script with only three arguments but reads a fourth (the ring scale); the exe's number reader returns 0 for a missing argument, so the retail rings are scaled to nothing and nothing is drawn. The empty stub was therefore correct (2.7 implements it for mods that pass the zoom; the game's own call still draws nothing). `drawForeground` (0x467330) only draws the foreground layer list, which no Space script fills. `setMenuParticlesScale` is only called for the iPhone 4 resolution switch. `createLineShape` is only used by the `STREAM_1` editor block.
- **Space background (`drawBackgroundNative`, 0x467f70)**: rewritten from the exe. Every layer (also the empty ones that only carry scattered elements) is placed with the camera snapshot taken at the first draw, the layer's `zDistance`, `scaleSpeed`, `xMult`, `yMult`, `angleMult` and `offsetX/offsetY`; looping layers are a row of copies, `createThemeSprite` elements are drawn on the layer index they name. Layers whose sprite is a composite (`THEME_1_BG_1` with its stars, `THEME_1_PARALLAX_3_LONG_VERSION_PC`) are drawn as composites; before, they were skipped, which left the flat blue screen.

- **Rio:** the bird pulled back in the slingshot no longer shows only its yell sprite; it blinks and squawks by the same timers as the waiting birds.
- **Rio and Space:** the trajectory dots, puffs and the aiming aid are drawn right before the first bird, so birds are in front of them (they used to be drawn over everything). The earlier games already drew them before the birds.
- **Space:** a level's own `gravityForceMultiplier` (1 in levels such as 1-19) is now used for the world; the engine always used the default of 4, so every planet pulled four times too hard in those levels (this was the gravity misread: the aim trail and the real flight bent down much too fast).
- **Space:** returning from an eggsteroid restores each object's radius, size and planet forces from the live level, which fixes the `radius` (a nil value) crash when the level draws again.
- **Space:** the aim trail now honours a planet's gravity filter (`gravityCollisionMask` against the bird's category), as the exe's gravity function does; `saveLevelForReload` really saves the level, which fixes the crash when entering an eggsteroid.
