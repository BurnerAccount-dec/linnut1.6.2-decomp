# Changelog

What changed in each version of the engine, newest first. The README has the current status; the reference for script writers is in [`docs/SCRIPTING.md`](docs/SCRIPTING.md) and how to run and debug in [`docs/USAGE.md`](docs/USAGE.md).

## New in 2.7

**Angry Birds Star Wars: the engine now follows the retail exe's physics and per-frame update.** Everything below is ported from the decompiled `AngryBirdsStarWars.exe` (addresses in brackets); the modding side of it is in [`docs/SCRIPTING.md`](docs/SCRIPTING.md#angry-birds-star-wars).

* **Contact filter and object flags (0x410e70).** Star Wars has its own rule for which two objects collide: collision groups (`setCollisionGroupIndex`, parameter 36), per-object material lists, kind 7 objects that never collide with each other and parameter 19 as the exception. The natives that set one flag of an object record (`setBlockCollisionEnabled`, `setIgnoresScore`, `setKeepOrientation`, `setAffectedByForceMultipliers`, `setIsWater`, `setWaterDensity`, `setControlled`, `setTimeSinceCollision`) are real now, not no-ops.
* **Water (0x41e440, 0x423270).** A gravity sensor flagged with `setIsWater` is a pool: boxes push up and circles pull towards their centre with a force that fades over the top 1.5 world units, with extra drag for birds (`setBirdWaterDrag`, 0.4) and objects (`setObjectWaterDrag`, 0) and a force multiplier for fresh birds (`setWaterForceMultiplier`, 2).
* **Collision damage (0x42f9d0).** Star Wars no longer runs the older games' damage rules. Forces divide by 10 after the config's `forceDamageMultiplier` (1); a bird hitting a block uses the momentum difference of the two (bird scaled by its damage multiplier and `powerupDamageMultiplier`), a HOMING bird that has not collided yet does a fifth of the damage, a block that dies takes the bird's velocity (at once with `useLegacyCollisionPath`, after the step otherwise) and the contact is switched off; two blocks take `force * factor - defence` (strength drops by the floor of it), `ignoresScore` objects score nothing, and the score added is `floor(damage) * scoreDamageMultiplier` followed by `addScoreToBird`. Damaging sensors (kinds 5, 6 and 7, unless the other object has parameter 20) hurt blocks with their definition's `damage`. `birdCollision` now receives `(a, b, force, damage, pointX, pointY, normalX, normalY)` and `blockCollision` `(a, b, force, wasDamageDone, false, damage, pointX, pointY, normalX, normalY)`, which the scripts' damage particles and collision actions read (they used to get nil). The first collision of a bird starts its gravity timer.
* **Hit wobble (0x42fe61).** Blocks with a `bounceAmplitudeMultiplier` (parameters 6 and 7) wobble when hit: the amplitude is `min(force * 0.02, 0.1)` and the phase of each object is shifted by its place in name order times a quarter turn. Two birds that collide start the same wobble unless an object has parameter 11 set.
* **End of contact and kill timers (0x41f370, 0x433464, 0x433771).** When a contact ends both bodies are woken, `exitTriggerCollision` fires for sensors (the sensor bookkeeping runs its exit side) and `exitCollision` always fires. A kind 4 sensor touched by a non-sensor, and an object with `stopOnExit` (parameter 34) leaving a flagged sensor, get a kill timer that the frame update counts down and then destroys the object. Sensors of kind 5 and 7 that drift beyond 0.88 times a level limit are removed straight away.
* **Per-frame object sync (0x433500).** `hasMovingObjects` ignores joints and any object with parameter 12 set and tests the absolute spin; `hasMovingObjectsZeroTolerance` is published (anything but a controlled object that moves at all); every awake object gets `objects.world[name].velocity` (the speed), which the scripts' specialty speed limit and drag threshold read; objects with the material `propeller` (and any object after `setRecordVelocity`) publish `xVel`, `yVel` and `angle` like birds do. Objects with parameter 9 (enable flipping) turn to face their direction of travel by calling parameter 8 each time they move faster than 3 sideways.
* **`createLineShape` (0x439640).** A body made of edge shapes, one for each pair of neighbouring vertices from `clearVertices` / `addVertex`, with the same arguments as `createPolygon` (Box2D 2.2 builds). The world entry has `type = "line"`. The retail game only uses it for the editor's `STREAM_1` block, but mods can use it for thin, one-sided or open terrain.
* **Aiming aid.** `populateAimingAid` (0x402770) lays the dots out along the stored trajectory, as the Space one does; the trajectory itself still comes from `updateBirdTrajectoryTable`.
* **`renderGravityVisualsNative` (0x415f90)** is implemented: circle sensors draw each entry of their `gravityVisuals` list eight times around the sensor and box sensors draw bars along their length. The game's own script calls it with three arguments, the exe reads the missing fourth (the zoom) as 0, and the retail game therefore draws nothing; the same happens here. A mod that passes the zoom as fourth argument gets the rings.
* **Level joints keep their fields.** `createJoint` stored only the values it used on `objects.joints[name]`, so a level-select scene (Endor, Death Star 2) lost `isDrawn`, `breakable`, `breakForce`, `jointPosX` and `jointPosY`; the retail scripts read them to draw vines and ropes (`gamescene.lua`) and to decide which joints break. They are kept now. `AB_JOINTDBG` also logs how many entries each `createJoints` call got, and `AB_DUMPLEVEL=<prefix>` writes one file per loaded level (`<prefix>.<level>.lua`).
* **Star Wars foreground layers (0x44b9xx).** With `NEW_THEME_SYSTEM_FOREGROUND` the theme's `fgLayers` only go through the new-system routine; the old positional/named foreground loop used to run as well, so Cloud City's foreground was drawn twice. Without the flag only the positional loop runs, and its fourth entry (scale) defaults to 1, not 1.5.
* **Stale joints after a tap.** `removeObject` clears `objects.joints` entries of the removed object in Space and Star Wars too (tapping a log or pig in a level select no longer leaves a joint pointing at a missing object, which stopped the draw loop before the buttons and cursor).
* **Release name.** `make_release.bat` writes `AngryBirdsEngine-v2.7.zip`.

## New in 2.6

* **Angry Birds Star Wars:** Princess Leia's gravity ray (a tall sprite drawn along the beam, one segment per phase) now runs from the bird along the beam direction via `drawTexturedLine2D`. Cloud City's foreground uses the new named layer format (`sprite`, `zDistance`, `scale`, `velX`, `offsetY`, `downFillColor`): the cloud band scrolls by itself and everything below it is filled with the layer's fill colour. Space's non-looping theme animations (the shooting stars of Red Planet) are removed when they reach their last frame, so `rePopulateWithRandomThemeSprites` can spawn the next one instead of the first staying forever. `AB_NOSCREENWIPE=1` switches the Classic wipe below off. Endor's level selection no longer stops with `themeSystem` nil: the native `themeSystem.spawnFGLayerParticles(id)` the scripts call (the ewoks particle layers of the foreground, found by `spawnerId`) exists now. The backgrounds of Star Wars' new theme system (`NEW_THEME_SYSTEM_FOREGROUND`, Cloud City and the others) are drawn at half the Space scale, which makes the sky, the domes and the clouds the size of the retail picture; `AB_BGK=<factor>` changes that factor for testing. Space's and Star Wars' frame animations of the theme (the shooting stars of Red Planet) are stepped by the engine every frame (their scripts call neither `rotateThemeSprites` nor `updateThemeSprite`), so a star that is not looping plays its frames, ends and is replaced by the next one instead of staying on its first picture. Hoth's foreground (snow plane and rocks) is drawn over all the level's blocks, so the rectangular ground blocks no longer show below the hills (`AB_FGEARLY=1` draws it behind them again, for comparison).

* **Star Wars natives from the retail exe:** `setRestitution(name, value)` (0x419d10, sets the bounciness of the body's shapes), `performBitwiseOr(a, b)` (0x40dcb0, `(int)a | (int)b`), `handleJointLimits(name, stop)` (0x410810: the motor of a revolute or prismatic joint that has reached the limit it turns towards reverses, or stops when `stop` is true; the exe's prismatic test only checks the motor and limit flags for the upper side, and the engine now does the same), `getFullScreenWidth()` and `getFullScreenHeight()`, `setWaterForceMultiplier(v)` / `getWaterForceMultiplier()` (0x40d490 / 0x40d4a0, the stored value), `fileExistsInAppData(name)` (0x421ee0), `loadTextFileToString(name)` (0x419560), `setJointParameters` and `handleJointLimits` now act on every joint that has the given name (0x411a20 and 0x410810 walk all joint records), `isGameOverlayActive()` (always false, as in the exe) and `clearScreen`, `refreshCurrentLocale`, `recoverRenderObjects`. Every name the retail exe registers now exists in the engine, either implemented or, for the ones no shipped script calls, as a do-nothing version (see the next entry).
* **Saves cannot be cut in half any more:** `settings.lua`, `highscores.lua` and the other save files are written to `<file>.tmp` first, the previous file is kept as `<file>.bak`, and the new file replaces the old in one step, so closing the window or a crash in the middle of a save leaves a whole file. At start-up a save that is missing, empty or unreadable is replaced by its `.bak` (the unreadable file is kept as `<file>.corrupt`), so progress is not wiped by a cut-off save.
* **Extra scripts for Classic 1.6.2 (screen wipe and aiming aid):** `extra_scripts.lua` also shows the Star Wars / Space aiming aid while a bird is pulled back: animated dots along the arc of the shot, drawn by the engine's own aiming aid (the Star Wars bird's `aimingAidSprite` when the game has it, else Space's light blue dot `TRAIL_AIM_1` / `TRAIL_AIM_BLUE`, which needs Space's `INGAME_PARTICLES_1.dat` and `.png` copied into the images folder, else `TRAIL_WHITE_1` scaled by `aimingAid.scale`). Like Star Wars' own aid it shows the bird's free flight (gravity only, no blocks and no ground) from the pulled-back position with the launch speed `shootSelectedBird` gives, step for step as the world steps (1/30 s, 10 + 10 iterations); it is shown even while an earlier bird is still flying and costs about 0.1 ms. New natives: `simulateAimingAid(bird, impulseX, impulseY [, points, startX, startY])`, `spriteExists(name)` and a scale argument for `setAimingAidSprite(name, scale)`. `getWorldGravity()` returns the physics gravity. Disable it with `aimingAid.enabled = false`. The screen wipe part: `extras/extra_scripts.lua` rebuilds the wipe Star Wars shows when a level is clicked: the picture on screen is kept with `res.captureSprite` and drawn over the new level while `res.setClipRect` takes the old picture away for one second (the old picture stays on the left and its right edge travels toward the left, so the new level opens from the right; `screenwipe.direction = "left"` in the script reverses it). Copy it to `data/scripts/extra_scripts.lua` (the engine loads it by itself in Classic 1.6.2) or add `loadLuaFile(scriptPath .. "/extra_scripts.lua", "", false, false)` to the end of `gamelogic.lua`. Only `loadLevel` and `setGameMode` stay wrapped; `update`, `drawMenu` and `drawGame` are wrapped when a level starts loading and given back when the wipe ends, so nothing of the script runs per frame outside a wipe. New native `res.keepLastFrame(true)` makes `captureSprite` take the last finished frame, so a capture asked for in the middle of a frame is not blank; it reads the screen back every frame while on, so the script switches it on only for the frame before a level loads.
* **Saves of the wrong game:** a Space or Star Wars `settings.lua` or `highscores.lua` found in the save folder of Classic, Seasons or Rio (its `playtime` is a table per device, which stopped Classic's `resetSettings` with an arithmetic error) is kept as `<name>.original` and the game starts with fresh saves.
* **Star Wars background parallax (Cloud City and the other new-theme levels):** `setStartingCameraValue(flag)` (0x40d8e0) is now a real native: it sets the flag that says the background's reference camera has been taken, so a script that calls it with `false` makes the next frame take the camera position the layers are measured from (before, it only stored a variable and the reference was taken from whatever the camera was on the first drawn frame). The reference camera and the first screen height are now dropped only when the theme changes (0x435f70), not every time a level of the same theme loads.
* **Background debugging:** with the environment variable `AB_DRAWDBG=1` the engine prints each Star Wars / Space background layer's numbers (`SPBG` and `SPBG2` lines: camera, reference camera, screen units, offsets) and every `setThemeOffsetY` call to the console, so a background that sits in the wrong place can be compared with the retail picture number by number.
* **Star Wars cutscenes no longer lag (the one after level 1-21):** a clip's keyframes were searched from the start for every target on every frame and each frame made new tables; every track now remembers the keyframe it was at, and a clip played once stops being stepped when it reaches its end (it stays on its last picture). New natives from the retail exe: `cutsceneStop(tag)`, `cutsceneStopAll()`, `cutsceneCloseAll()` and `cutsceneSeek(tag, time)`.
* **Classic 1.6.2 story cutscenes lag (the one after level 1-21):** `extra_scripts.lua` (now version 6) switched the screen read-back for the wipe on whenever the loading screen came up and only switched it off when a level loaded, so a loading screen that led to a story page left the read-back running every frame. It is now switched off by itself three seconds after a loading screen that was not followed by a level. Copy the new `extra_scripts.lua` to `data\scripts`; the console line should say `version 6`.
* **Star Wars / Space `drawTexturedLine2D` (Leia's ray and every other beam):** the retail routine (0x425b20 with the corner maths of 0x425810) always lays the sprite's height along the line from the first point to the second and its width across the line, with the picture's left side on the left of the direction of travel; the engine did that only for sprites that looked tall and laid every other sprite sideways. Classic, Seasons and Rio keep their own rule (the rubber bands).
* **Star Wars Cloud City background:** a layer of a theme with `NEW_THEME_SYSTEM = true` that has no `xMult` now gets 0 (the retail layer loader's default; Space and the older themes keep 1), so the Cloud City layers no longer slide sideways with the camera by a factor the exe does not apply.
* **Remaining Star Wars natives:** the last registered names of the retail exe that were missing now exist: `setGameRenderingDisabled` / `isGameRenderingDisabled` (0x40d880 / 0x40d8a0, they keep the flag), `getUnlockRequestChecksum` (toy-code check for a server that is gone, returns an empty string) and do-nothing versions of `toggleZoomSteps`, `setPhysicsScale`, `setFlashAnimation`, `updateThemeParticlesNative`, `loadLevelFromAppData`, `loadLuaFileFromAppDataToObject` and `native_loadTextFileToLuaTable`, which no shipped script calls. The reference camera is read again with every level; a level saved for other devices only takes the first camera entry it has (`windows`, `pc`, `mac`, `ipad`, `iphone`, then any), and until the level data has been seen the camera of the moment stands in (so layers are not thrown off by a camera that is moved after the first frame).
* **Star Wars NEW_THEME_SYSTEM backgrounds rewritten from the retail routine (0x44c1b0 and helpers 0x44a030 / 0x44a1a0 / 0x44a320 / 0x44bfa0 / 0x44bdf0 / 0x44b820):** the retail exe draws themes with `NEW_THEME_SYSTEM = true` (asteroid fields, Hoth high orbit, Cloud City and the other newer Star Wars themes) with a different routine than the one used for Space and the old themes, and it uses no reference screen size at all. A layer is placed in world coordinates relative to the level's reference camera (`objects.castleCameraData[deviceModel]` px / py / sx, or the first frame when the level has none; `g_useLowerCameraAsThemeReferencePoint` and `g_useZeroAsThemeReferencePointX/Y` are honoured), moved by its zDistance and xMult, sized by `z + worldScale / referenceScale * (1 - z)` times scaleX / scaleY, and drawn through the camera (`screen = (world - camera) * worldScale`). The `flags` strings are read (H_REPEAT, V_REPEAT, REPEAT_LEFT_ONLY, REPEAT_RIGHT_ONLY, ANCHOR_V, PREVENT_STRETCH_SCALE, OVERSTRETCH_ANCHOR_V) and the layer is repeated like the retail loops. This replaces the earlier fitted half-size scale for these themes (`AB_BGK` now only applies to the old themes). `AB_DRAWDBG=1` prints `NTREF` (the reference camera) and `NTL` (every layer's size and screen position). The foreground layers (`fgLayers`) of these themes now go through the same routine (retail keeps them in the second layer vector of the same system), with the `downFillColor` / `upFillColor` bands drawn from the layer's edge, and `setThemeOffsetY` follows 0x412760 for them: it replaces the layer's posY with the table offsetY plus the value, scaled by 768 / screen height only for a layer whose own `elements` table is empty.
* **Star Wars night backgrounds (Hoth space levels, asteroid fields and every other Star Wars theme):** the reduced background scale (0.7 of the Space size, fitted to the retail star pattern: 301 px repeat against 217 px at 0.5) now applies to every Star Wars theme (recognised by the `textureScale` entry in its table), not only the ones marked `NEW_THEME_SYSTEM_FOREGROUND`; the old-format Star Wars themes were drawn at double size, so their star layers started far below the top of the screen. Angry Birds Space themes are unchanged. `AB_BGK=<factor>` still changes the factor for testing.
* **Layer sprite lists and relativeY (Star Wars NEW_THEME_SYSTEM):** a layer whose `sprite` is a list (the asteroid field's stone layers) keeps the list as its animation frames. Retail reads `spawnParameters.amount` and throws the value away (0x44adb0: `fstp st(0)`), never reads `xSpeedVariance`, and only re-places the layer inside its spawn area when the layer has the REFRESH_ANIMATION_COORDINATES flag (0x10); a layer without `flags` starts with 0, so each stone layer is one stone that drifts by `velX / velY * (1 - zDistance)` and jumps back by whole widths once it has left the screen (0x44b200). A layer with `relativeY` (the Bespin 2 floor filler) has its y offset set to `screenHeight * relativeY - screenHeight / 2`, which replaces its own `offsetY` (0x44b820, first call; `setThemeOffsetY` later replaces it again). `native_refreshThemeSystem` (0x44a950) takes the reference scale from `originalCameras[2].sx`, the level's own castle scale, which the port already uses. The wrap shift is `scaleX * width * (1 + trunc((right - left) / (scaleX * width) * referenceScaleX))` and the same with the height (read from 0x44b200's code; before it used the on-screen size).
* **Foreground reference y (Star Wars NEW_THEME_SYSTEM):** the foreground layers (`fgLayers`) use the world y of the screen's top edge as their reference y every frame (0x44c1b0 overwrites ThemeSystem +0x20 for mode 0), so they take no vertical camera shift.
* **Moon of Endor:** `themeSystem.spawnFGLayerParticles` is registered with the engine, so the level selection no longer crashes.

## New in 2.5

* **Space graphics:** planets (and any decoration) now draw at the retail size: a decoration's scale is multiplied by its object's scale, so the craters of `PLANET_BASE_SLICE_*` line up. Space backgrounds that are composites (several layers, drawn with the composite's extent) draw like the retail `drawBackgroundNative`.
* **Space level editor:** press **F2** in a running Space level. Left drag moves an object, **N** places the chosen block at the cursor, **D** copies the selected object, **Q / E** turn it (Shift = fine), **Delete** removes it, **PageUp / PageDown** (or Shift + wheel) choose the block, arrows pan, the wheel zooms, **Ctrl+S** saves the level, **F2** again plays on.
* **Angry Birds Star Wars (work in progress):** its scripts are now readable. They are AES-256-CBC encrypted with the Star Wars key (Star Wars II has its own key too, both are tried after the older keys) and the decrypted data is a 7-Zip (LZMA) archive holding the compiled script, which the engine unpacks itself. The game uses the Space layout (`scripts_common`); `options.lua` is run when the game logic does not define `releaseBuild`, and the `ResourceManager.native_*` functions the scripts call are mapped onto the engine's own natives (unknown ones are harmless no-ops). The game now boots through its splash, the initial loading and into the main menu. `res.createCompositeAudio` (a sound made of other sounds that play one after another, such as the title theme followed by the menu music) is implemented; before, `startInitialLoading` failed half way and started again every frame, so the log repeated "Start initial loading" forever. The cutscene natives are implemented: `cutsceneLoad`, `cutsceneStart`, `updateCutscene`, `drawCutscene`, `cutsceneSetTranslation / Scale / Rotation` and `cutsceneClose` play the game's animation files (encrypted JSON: a tree of targets with translation, scale, rotation and sprite tracks, layer 0 on top). `captureSprite` makes the last frame a sprite (the screen transitions), `particles.native_addParticlesWithMode` and the three particle layers (background, foreground, notifications) work, `setMass` changes the density of a body, and the device-only calls (font and UI scale, window state, social checks) answer like a full-screen PC window. Levels now load and run with their sprites. Slow-motion birds (Obi-Wan, the Force powers) now work: the delta-time multiplier set by `setDeltaTimeMultiplier` scales the time step of each frame, as in the exe. The mouse wheel zoom is kept apart from the world scale in Space and Star Wars (`setWorldScale` only stores the scale, `resetMouseWheelScale` sets the wheel zoom), and the 0.01-100 limits the exe does not have are gone. `drawUITextNative` takes the text's alpha as its seventh argument in these games (it was read as a scale, which made fading texts such as the quit prompt grow and drift off their pivot). Tatooine's foreground layers are drawn by the engine (the exe draws them itself, the scripts never ask), the cheat menu (`QAPage`) now loads in Star Wars and Space even when `cheatsEnabled` is set after start-up, the credits crawl of Star Wars is drawn by `drawString3D` (text laid on a tilted plane that fades into the distance), and `drawUITextNative` keeps the caller's translation so Space's credits text follows its parent object. Star Wars saves (settings, highscores, bi_data, episodepurchases) are written with the game's own save key, so the retail game reads what the engine writes and the other way round; the highscores keep the retail layout of one top-level table per level. A composite sprite that is drawn turned (the menu's TIE fighters) now turns as one piece: each part's pivot is moved by where the part sits in the composite, so every part rotates about the composite's origin instead of its own corner. `AB_THEME=<theme name>` draws that theme's background in any level (a test aid for checking themes whose sheets are not in the level's own load list).

Still open in Star Wars: water, trajectory preview of the power-ups, and the collision rules of `setBlockCollisionEnabled`.
* **Saves written by another build of a game:** a settings or highscores file the engine cannot decrypt is kept as `<name>.original` and the game starts with an empty one, instead of failing with a Lua syntax error.
* **Space splash:** the splash screen is always drawn on a black full-screen rectangle.
* **Invisible Space markers:** sensor sprites (`GRAVITY_SENSOR_*`) and objects of scale 0 are editor markers and no longer draw (this was the blue dot where a level's pig spawns).
* **`getHardwareModel`:** implemented (returns the `deviceModel` of `config.lua`, `windows` by default), which scripts for tablet builds call at start-up.
* **Save folder:** two games with the same `product` in `config.lua` share one save folder and read each other's save format. Give a game its own `product` if it has a different save format.
* **Space natives:** `getAimingTime`, `removeBreakableJointsFromObject`, `addGravitySensor` and `setThemeOffsetY` are implemented. Still stubs: `linkSensor`, `createLineShape`, `drawString3D`, `renderMaskedImageNative`, `drawSelectedTexturizedObject`, `drawRubberband`.
* **Space moving backgrounds:** the elements a theme lists in `bgLayers[...].elements` (planets, clouds, asteroids) are created and drift every frame like the retail exe's layer update (`velX`/`velY`, and `scaleSpeed` for comets), so the backgrounds are no longer still. Scripts that scatter their own elements (`populateWithRandomThemeSprites*`) keep doing so.
* **Incomplete Space builds:** an error in `update` or `draw` is now printed once ("script error (skipped...)") and the frame is skipped instead of closing the game, so builds with missing scene scripts or block files keep running. Set the environment variable `AB_STRICT=1` to get the old behaviour (the first script error ends the run).
* **Space builds that never load their block files:** when the scripts have no `loadBlockData` and `blockTable` does not exist, the engine loads the block, material, damage-factor, group, theme, texture, world-attribute and particle files itself, in the retail order, before the first scene. Without this `blockTable` stayed nil and nothing in a level could draw. `setCurrentLevelPack` / `getCurrentLevelPack` are provided for scripts that call them.
* **config.lua globals:** `deviceModel`, `isLiteVersion`, `isBetaVersion`, `audioPath`, `localizationPath` and `levelPath` are now read from the game's `config.lua` and given to the scripts, which is how Space builds choose their asset folder (for example `deviceModel = "meego"` with `isLiteVersion = true` loads `images/864x480_lite`). Without this such builds start but draw nothing.
* **Sensor contacts for every game:** `enterCollision` and `exitCollision` are called for sensor contacts in any game whose scripts define them (see below).


## New in 2.4

Version 2.4 adds the Angry Birds Space fixes that followed 2.3 and a set of new script functions for modding. In short:

* **Space:** the level limits and the draw order now follow the retail exe (the Utopia 4-30 crash and Red Planet 5-30 are fixed), and single-folder Space builds load.
* **Objects and physics:** `setScale` / `getScale`, `setSpeedCap` (a speed limit for one object that replaces `setMaxTranslation` for it), `getTouchingObjects`, `rayCast` (nearest hit or every hit along the ray) and `fileExists`.
* **Audio:** pitch, tempo and stereo pan per clip (settable before the clip plays), seeking inside a playing clip, reading its position and length.
* **Graphics:** blend modes, built-in shader presets (grayscale, sepia, invert, chromatic aberration, glow), single tint channels, a visual-only rotation, a pixel colour lookup, a composite sprite part list, and a **target** argument that lets the graphics settings apply to one object, sprite, composite sprite or to the background, foreground, trajectory dots and particles. All of it also works on tiled texture blocks.
* **Text and console:** `res.setString` injects new text; the console gained `text`, `texts`, `gravity`, `maxtranslation`, `scale`, `speedcap`, `blend` and `shader`.
* **The command prompt** closes together with the game when the game is closed normally, and stays open after a crash so the message can be read.

**Space level limits.** `setLevelLimits(minX, minY, maxX, maxY)` keeps all four limits and an object that moves outside them is removed; the old rule (anything below y 20 is gone) is now only used by the other games. It made the Utopia boss (4-30, which spawns its popcorn at y 60) and the Red Planet boss (5-30) delete themselves on the first frame, and removed birds that flew low in some planet levels.

**Space and Rio draw order.** See "Draw order and z": one pass over the z layers, as the exes do.

## New in 2.3

**Angry Birds Space compatibility update.** Space's physics now follows its own exe instead of Rio's: its Box2D is a mix of 2.2 collision with 2.3 broad phase, island, sleep and solver rules (rotating dynamic tree, position-solved sleeping, 2.3 position-solver constants, a larger time-of-impact island, `setStatic` through `SetType`). The planets' pull, the aiming aid and the per-object gravity functions share one code path that follows the exe's gravity function. See "Engine-added script functions: full reference" for the new script functions.

**Space natives that used to do nothing.** `setRecordVelocity(name, on)` (publishes `xVel`, `yVel` and `angle` into `objects.world[name]` for that object), `applyForceNative(name, fx, fy, px, py)` (the same force as `applyForce`) and `setRevoluteJointSpeed(jointName, speed)` (sets the motor speed of the joints with that name, as the exe does), `setSpriteRotation(name, angle)` (the sprite turns by this much on top of the body's angle), `setPivotOffset(name, x, y)` (moves the point the sprite turns about), `setTextureScale(name, scale)` (stored; the tile draw does not use it yet) and `drawTexturedLine2D(sprite, x1, y1, x2, y2, width [, r, g, b, a])` (the sprite stretched along a line, used for the slingshot's rubber bands), `setNormalTrailSprite(name)` / `setSpecialTrailSprite(name)` (the dot and puff sprites of the trajectory the next shot draws) and `setDecorationObjects(name)` (the copies of a block definition's `decorations` sprite drawn about the object, as on the huge planets) now work.

**More Space natives.** `createThemeAnimation(table)` (a theme sprite whose picture cycles through the `animation` list every `animDelay` seconds; fixes the Red Planet crash), `getLinearVelocity(name)` (`vx, vy`), `getBGColor()` (`r, g, b`, 0 to 255), `getRayCastedObjects({x1=, y1=, x2=, y2=})` (a flat list, six entries per non-sensor object the segment crosses: name, hit x, hit y, normal x, normal y, fraction) and `createCompoundBodyFromTable(t)` (a compound built from a table with `name`, `x`, `y`, `material` and `children`, each child with `x`, `y`, `angle` and a `blockData` of type box, circle or polygon). `addParticlesWithScale` and `addParticlesWithProperties` now apply their extra arguments, and Space particle definitions honour `useAngleFromSpawner`, `minAngle` / `maxAngle`, `emitAreaScaleX/Y` and their own `ignoreLimits`.

**Space planet gravity.** The pull follows the exe's contact list: one entry per touching fixture pair (an object made of several fixtures is pulled once per pair), applied last entry first and only to objects that are awake; a gravity sensor with parameter 19 sets the linear damping of objects flagged with parameter 1 or 34 to 100 when they leave it.

## New in 2.2.3

**Reading and changing the z of objects.** Everything about the `z_order` of blocks can now be asked for and changed from the scripts and the console (the rules of the draw order are under "Draw order and z"):

| Call | Meaning |
|---|---|
| `getObjectZOrder(name)` | the object's current `z_order`; `nil` if there is no such object (before: -1e9) |
| `objects.world[name].z_order` | the same value, from the table the scripts already read. It is kept up to date: `setObjectZOrder`, `bringObjectToFront`, `sendObjectToBack` and the console commands below write the new value into it |
| `setObjectZOrder(name, z)` | sets it (as before; now also updates `objects.world`) |
| `bringObjectToFront(name)` | puts the object in front of every other one and returns its new `z_order` (the highest z in the world plus 1, at least 5, so it is in the group that is drawn last in every game); `nil` if there is no such object |
| `sendObjectToBack(name)` | puts it behind every other object of its group (the lowest z in the world minus 1) and returns the new `z_order`. The static blocks below z 5 are drawn first whatever z the others have, so a moving block cannot go behind those |
| `getObjectDrawOrder()` | a table of object names from the back to the front, in the order `drawGameNative` draws them (the trajectory dots are not objects and are not listed) |
| `getRenderZ()` | the `z` of the current render state (`setRenderZ(z)`, which already existed, changes only that value) |

Console: `zorder` lists every object back to front with its `z_order`; `zorder <name>` shows one and where it is drawn; `zorder <name> <z>` sets it; `zfront <name>` and `zback <name>` bring it to the front or send it to the back. For example `zorder BLOCK_WOOD_3 20`.

## New in 2.2.2

**Draw order and z.** The `z` of `setRenderState` and the `z_order` of blocks are now one scale: a sprite drawn after `drawGameNative` with a lower `z` than some blocks is drawn below those blocks, and the other way round. Without any `z` set, every game draws exactly as before (compared pixel for pixel on Rio levels and the Classic menu). See "Draw order and z" below.

**Choose the Box2D version in `config.lua`.** Add `box2d = 21` (Box2D 2.1, the Classic and Seasons physics) or `box2d = 22` (Box2D 2.2, the Rio physics) to the game's `config.lua`; `"2.1.1"` and `"2.2.0"` work too. ## New in 2.2

**Video.** `playVideo(videoPath .. "/" .. name)` plays an MP4 / M4V inside the engine window, no other program. On Windows the picture is decoded by Windows Media Foundation (every H.264 profile, like the sound); everywhere else, and when Media Foundation cannot open the file, the built-in baseline decoder is used. It looks for the file as given, then under the data folder and `videos/`. Click, Space, Return or Escape skip it; the Lua call returns when it ends. `videoPath` is a Lua global filled from `config.lua` (`videoPath = "videos"`), so it can be read and changed from the scripts. `stopVideo()` and `isVideoPlaying()` also exist. The sound track needs AAC decoding, which is done through Windows Media Foundation (Windows only; without it the picture plays silently). Decoder: h264bsd (`third_party/h264bsd`, own licence).

**`setRenderState(tx, ty, sx, sy, angle, pivotX, pivotY, alpha, skewX, skewY, bendX, bendY, z [, bendFunction])`.** Arguments 9 to 17 are new and optional (15 to 17 are the tint, see below).

| Argument | Meaning |
|---|---|
| `skewX`, `skewY` | shear about the pivot (units: shift per unit of height / width), applied before the rotation |
| `bendX`, `bendY` | how far the middle of the sprite is pushed sideways / up, in pixels; drawn as an 8x8 grid |
| `z` | draw order of the sprite (and of `drawRect` / `drawLine2D`) against the game's blocks and other sprites that use `z`; 0 means "in the order the script drew it". The same scale as a block's `z_order`. See "Draw order and z" |
| `bendFunction` | optional Lua function `f(t, 0, 1, 1)` with the same arguments as the gamelogic tweens (`tweenLinear(currentTime, startValue, changeOfValue, duration)`); it is sampled 9 times and its curve shapes the bend. Without it the bend is an arch (sine) |

`setObjectZOrder(name, z)` / `getObjectZOrder(name)` set the draw order of one block (Rio's own `zOrder` still works; in other games a group with a z-ordered object is sorted by it). Both kinds of z are on one scale, see "Draw order and z". The debug overlays drawn by `drawRect` and `drawLine` (the 8 key) now rotate with the body.

**Speed.** `physicsSpeedFactor` (Lua global) now changes only the physics step rate; the scripts' `update(dt)` is untouched. `gameSpeedFactor` multiplies the time step of everything (physics, scripts, animation). Both are read every frame, so `gameSpeedFactor = 0.5` in a script or `set gameSpeedFactor 0.5` in the console works. Defaults 1.

**Frame rate.** The window now runs without waiting for the monitor (vsync off) and without a cap, so on a fast machine it renders far above 60 fps. `fps 120` caps it, `fps 0` removes the cap, `vsync on` waits for the monitor. Start options: `--fps N`, `--vsync`.

**Audio.** From the console or Lua (`res.` functions): `audiospeed [x [track]]` / `res.setAudioSpeed(x)` change playback speed (pitch follows), `audiopause` / `audioresume [track]`, `mastervolume [v]`, and `res.setAudioClipVolume`, `res.setAudioClipSpeed`, `res.getAudioSpeed`, `res.isAudioPaused`, `res.getMasterVolume`. At speed 1 the mixer path is unchanged.

**Startup commands.** `--cmd "<console line>"` (repeatable), `--startup <file>` (one console line per file line) and `--prompt` (or `AB_PROMPT=1`: an `ab>` prompt before the game opens, an empty line starts it) run console commands before the first frame.

**Console.** New: `fps`, `vsync`, `gamespeed [x]`, `physicsspeed [x]`, `set <name> <value>` / `get <name>` (any Lua global), `audiospeed`, `audiopause`, `audioresume`, `mastervolume`.

**Editor.** Saving a level into a folder that does not exist now creates the folder; an absolute path is used as it is.

**Tint (`setRenderState`, arguments 15 to 17, and dedicated functions).** Sprites can be multiplied by a colour: red, green, blue from 0 (none) to 1 (unchanged); above 1 brightens. Like alpha it affects what is drawn after it and is reset when the engine starts a new drawing pass, so set it right before the sprites you want tinted.

    setRenderState(0, 0, 1, 1, 0, 0, 0, 1, 0, 0, 0, 0, 0, nil, 1, 0.3, 0.3)   -- ..., z, bendFunction (nil), tintR, tintG, tintB: reddish
    _G.res.drawSprite("BIRD_RED_YELL", 200, 250)

The single values also have their own functions, so you do not have to repeat the others:

| Function | Effect |
|---|---|
| `setTint(r, g, b)` / `setTint(grey)` | tint of what is drawn next, for example `setTint(0, 1, 0)` |
| `getTint()` | returns r, g, b |
| `resetTint()` | back to 1, 1, 1 |
| `setAlpha(a)` | transparency, 0 to 1 |
| `setSkew(x, y)` | shear (arguments 9, 10) |
| `setBend(x, y)` | bend (arguments 11, 12) |
| `setRenderZ(z)` / `getRenderZ()` | the z of the render state alone (argument 13 of `setRenderState`), see "Draw order and z" |
| `setBlur(pixels)` / `resetBlur()` | sprites are smeared over this many pixels (nine copies, each with 1/n of the alpha; `setRenderState` argument 18); 0 is sharp |
| `setPixelate(size)` / `resetPixelate()` | sprites are drawn in blocks of size x size sprite pixels, at most 64 x 64 blocks (`setRenderState` argument 19); 0 is off |

Example: a faded green bird, then the next sprite normal again:

    setAlpha(0.5) setTint(0, 1, 0)
    _G.res.drawSprite("BIRD_RED_YELL", 300, 250)
    setAlpha(1) resetTint()

## Changes since 2.1

Everything below was added after the 2.1 release and is part of 2.2. It is grouped by what it touches; the physics work is a comparison of the engine's functions with the Ghidra decompile of each retail exe.


### Lua compiler fix (constants beyond 256)
In a function with more than 256 constants, an expression such as `x + 800 * t.dir.x` was compiled so that the constant's register was overwritten by the second operand, giving `x + t.dir.x * t.dir.x`. The compiler now evaluates the second operand first (the same order later Lua versions use), for arithmetic and comparisons. Large scripts, such as a long game-logic file, now calculate these expressions correctly.

### Physics: Angry Birds 1.6.2 and the other Box2D 2.1 games (Classic, Seasons)

- Continuous collision follows the exe's own routine (the time of impact pass ported from 0x4e70d0): the earliest impact of all contacts that involve a static body is found, the bodies are moved there, the touching island is solved with the rest of the step and the pass repeats. `AB_OLDTOI=1` brings back the bundled Box2D routine, `AB_NOCCD=1` turns continuous collision off.
- `b2Contact::Update` checks the overlap of the two fixtures' boxes before it runs the narrow phase, as the exe does; the wake-up rules of `b2Body` and the term order of `Solve33` in `b2Math` match the exe.
- The island solver, the position solver's equalised mass and the TOI island follow the exe. Blocks are created awake, and every level load starts a brand new physics world (`AB_KEEPWORLD=1` restores the shared world). A restarted level now settles like the first load.
- Revolute and prismatic joints with both a motor and limits reverse at their limits by themselves (the Classic scripts never call `checkJointLimits`), which makes the Golden Eggs pickaxes move.
- The Eagle can be used once per level, as in the retail game.
- Seasons 1.0.0 to 2.2.0 use the same Box2D code as 1.6.2; the exes differ only in compiler inlining, so no separate physics is needed.

### Physics: Angry Birds Rio 1.4.2

Rio's exe contains a Box2D 2.2.0 trunk build with its own time of impact solver, which the engine now follows:

- `Island::SolveTOI` works on the earliest-impact contact, advances each body's sweep, and the "leap of faith" that commits the new positions applies to **every** body of the island, not only the two bodies of the contact.
- The group of bodies of a time of impact island stops growing at 32 bodies (`b2_maxTOIContacts`), the contact list has room for 4 times that.
- Contact partition, the sleep condition (it no longer depends on whether the position solver finished), the position solver's mass normalisation, its -1.5 x linear slop threshold and the TOI position solver (which moves both bodies) match the exe. Constants: linear slop 0.05, TOI target 0.15, tolerance 0.0125, 20 position iterations, Baumgarte 0.75.
- Rio instruction matching (v2.2): the position solver subtracts both radii in full (`b2_solverSkinFraction` = 1), the circle manifold returns the normal (1, 0) for coinciding centres, revolute and prismatic joints use the exe's 2.1-style Init / SolveVelocity / SolvePosition (including the large-detachment step), `b2Mat33::Solve33` uses the exe's term order, `b2Body::SetType` / `ResetMassData`, `AddPair` (no waking) and `Collide` (awake test) follow the exe, and the world is stepped with 10/10 iterations. Smuggler's Plane 1-10 still holds and 12-15 stays stable.

### Physics: how closely it follows the exes

The Box2D code of each game was compared, function by function, with the Ghidra decompile of that game's exe:

- **Angry Birds Rio 1.4.2** (`AngryBirdsRio.exe`, Box2D 2.2.0 trunk with 2.1-style joints): every Box2D function the engine uses was compared and made to follow the exe, including the order of the floating point terms. That covers the world step and solve, the time of impact pass, the contact manager (AddPair, Collide), the contact and position solvers and the polygon / circle manifolds, the island solve, the revolute, prismatic, weld and distance joints, bodies (SetType, mass data), the shapes' mass, centroid and ray casts, the GJK distance routine, and the dynamic tree and broadphase (the exe has the older 2.2.0 tree with a rebalance pass after each pair update, which decides the order contacts are created in).
- **Angry Birds 1.6.2** (Box2D 2.1.0): the world, the time of impact pass, the island and contact solvers, the joints and the collision functions follow the exe.
- **Angry Birds 2.0.0**: its decompile was compared with the 1.6.2 one. Of the Box2D functions, all but a few dozen are identical after the names are stripped, and the rest differ only in addresses, so 2.0.0 runs the same physics as 1.6.2.

What cannot be matched is the last bit of `sin`, `cos` and `sqrt`: the exes call the x87 versions, the engine uses the host's math library. Apart from that the physics in these games is the exes' physics. This was done by reading the decompiled code, not by comparing with recordings of the retail games, so a mistake in a function the engine does not run (or in a case no level reaches) would not have shown up.

### Drawing and speed

- **Static blocks that tile a texture draw correctly again.** A file used both as a sprite sheet image and as a repeating block texture is now kept as two textures (one that repeats, one that does not). When both wanted the same file, terrain showed as one flat colour.
- **Textures are uploaded when the sprite sheet is created**, behind the loading screen, like the exe does, instead of on the first draw. The frames after a menu or a level opened used to stutter, the more so the more sheets a game has.
- **A sprite name that is in no sheet is remembered**, like one that is. Before, every `drawSprite`, `getSpriteBounds` or `getSpritePivot` call with a name that does not exist walked every sprite of every sheet (about 40 microseconds in Rio, per call); scripts that measure or draw such names for each object each frame lost many milliseconds per frame. Composite sprite lookups are remembered too (a missing name now costs about 2.5 microseconds).
- **The hand cursor** (`CURSOR_*`) is now drawn at the very end of the frame, on top of everything the scripts and the engine draw (a background, a panel or the game drawn after the script's cursor call used to cover it, as in the Seasons editor), with the clip rectangle off and with z, blur, pixelation, transparency and tint of the sprites before it taken away. The system cursor is only hidden when a cursor sprite was really drawn that frame.

### Angry Birds Space (PC)

Space's menus and levels load, draw and play: the level is built by the scripts, the planets pull the birds and blocks (gravitation sensors, Box2D 2.2.0 like Rio and no world gravity), the slingshot launches the bird and the aiming aid draws its dots. Only the first theme's levels were tested. Still approximate: the background layers (positions and parallax), the aiming aid (it flies the bird on alone under the sensors and ignores what it would hit), the foreground, and the compound bodies, particle scale and several shader and font natives, which are provided but not tested against a level that uses them.

- Space's scripts are AES encrypted with their own key, which the engine knows; they are read from `scripts_common` as well as `scripts` (`config.lua`'s `commonScriptPath`).
- The natives Space's `gamelogic.lua` expects at start that the other games do not have (bitwise or, vector helpers, device id, time differences, Flurry and logging calls, timers) are provided by a built-in Lua file, `space_natives.lua`.
