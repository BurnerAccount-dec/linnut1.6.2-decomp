# Changelog

What changed in each version of the engine, newest first. The README has the current status; the reference for script writers is in [`docs/SCRIPTING.md`](docs/SCRIPTING.md) and how to run and debug in [`docs/USAGE.md`](docs/USAGE.md).

## New in 3.9

- **A stand-in server for Angry Birds Social is part of the repository** (`social-server/`, needs Node.js). Sign-in shared by every Social page, the level editor, sharing and high scores, an Avatar Creator, a Players page with everyone's profile and levels, and the bridge that turns Social levels into Classic level files and back. It can be run for other players over a network or the internet (`HOSTING.txt`): passwords are hashed, there are limits per address and for sizes, and sessions do not mix up players behind one router. The game's own files are not included.
- **Pop-up episode style:** `episodes = { style = "popup" }` in `episodes.lua` swaps the picture tiles of 1.6.2 / 1.6.3.1 for the mobile pop-up boxes, which grow under the cursor.
- **An episodes file for the menu before 2.0.0 (Angry Birds 1.6.2 and 1.6.3.1).** Before 2.0.0 the episodes are written out in `gamelogic.lua`; since 2.0.0 they are one table in `episodes.lua`. `extras/episodes.lua` (copy it next to `gamelogic.lua`, with the new `extra_scripts.lua`, version 19, section 10) brings that to the old menu. For each of the six episode pages it sets the levels of every world and the folder they are read from (`episodes[n].worlds = { { folder = "mypack", levels = { "MyLevel", "Level1" } } }`; a world may hold fewer levels than its page, the rest stay empty), the art of the episode tile (`tile`, the picture of one of the six stock episodes) and the order of the tiles on the episode screen (`order = { 2, 1, 3, 4, 5, 6 }`). Scores, stars and locks follow their episode. A file with every line commented out changes nothing. Seasons (2.3.0 and before) reads the same `episodes.lua` too, loaded by the engine itself: `episodes.packs = { pack2 = { "LevelX_39", "LevelV_3" } }` sets the levels of a pack by its name, before the menus are made from them (the season and episode lists use the same tables, so they follow). See "Episodes file" in `docs/USAGE.md`.
- **Social levels in the game (Angry Birds 1.6.2).** F12, in a menu or in a level, opens a list of the levels of a stand-in Angry Birds Social server (`extras/extra_scripts.lua`, section 9, table `socialLevels`): Up / Down choose, Left / Right turn the page, Return or a click plays the level as a Classic level, Escape closes. Two new script natives make it work and are there for any script: `httpGet(url [, seconds])` (the body of a plain `http://` page, or `nil` and a reason) and `playLevelText(text)` (starts a level given as the text of a level file, as dropping the file does; a level file dropped on the window uses it too). The list shows the best score of every level, the score of a cleared level is sent to the server under `socialLevels.player` (`socialLevels.sendScores = false` turns it off), and the server's `/classic/live` page shows who is playing.
- **A dropped level can be cleared.** The level-complete screen reads the level's silver and gold score limits, and a dropped level had none, so the game stopped with a script error when the last pig was gone. A dropped level now has limits of 25,000 and 75,000 points.
- **Angry Birds 1.6.2: round static rocks.** The engine adds `StaticBlockThemeNN_07`, `_08` and `_09` for every theme: the theme's square static rock as a circle of 41, 103 and 207 pixels across (2, 5 and 10 cells of the Social level editor). The round picture is made by the engine and the theme's ground texture is drawn through it, like the square rocks. A level file can use them like any other block.
- **Angry Birds 1.6.2: key 8 no longer breaks the game.** The hit-box debug view reads `blockTable.blocks[definition].strength` for every object, and a bird, pig or prop with no block definition stopped the update with `attempt to index field '?'`. A definition that is not in the table now reads as an empty one, so the view draws and the game goes on.
- **A level file dropped on the window now plays.** Outside a level (menus, level select) the dropped level starts like a level picked from the menu: the game's own loading mode loads it, then the birds, the slingshot, the physics and the keys all work, and the camera pans over the level. Before, only the blocks were put on the screen and the game stood still. Inside a level, a drop still spawns the level's objects into it (the level spawner).
- Angry Birds Stella: the z-layer passes of the game picture now work like the original (`setZOrderRange` limits what each of the two draw passes shows), so objects are no longer drawn twice, the tree leaves are solid again and the strawberries sit inside the bucket. The Stella native `setSprite` no longer calls itself forever (that stopped the level from starting its camera, slingshot and bird queue). `getLevelLimits` (the butterfly jars use it) now returns the limits the level set instead of zeros.
- **Stella: the game's shaders are used.** The ability's trail, the block highlight and the other sprites the scripts draw with a shader (`2d-sprite-colorize`, `2d-sprite-gold`, `2d-sprite-diffuse-modulate`) were drawn without it. They now use the game's own pixel shader (data/shaders/pixelShaders/pp.ps), with the values the scripts set: `DIFFUSEC` (the phone reads four numbers from it and a missing fourth is 0, so Stella's red trail has alpha 0 and glows), `LIGHTNESS`, `SATURATION`, `HIGHLIGHT`. Objects that carry a shader are drawn with it too. Needs the OpenGL renderer; the software renderer draws them plain as before.
- **Stella: three native functions the abilities and scripts call were missing and silently did nothing**, now matched against the iPhone executable: `native_setDensity` (Willow's roll and Stella's ability change the bird's density with it), `native_setSprite` (sprite changes made through `setSprite` in the scripts) and `native_getSimpleRandom` (the scripts' seeded random numbers: the phone's 32 bit integer and float arithmetic, so the same seed gives the same numbers).
- **Stella: levels load with a bird skin chosen.** The level build read the Telepod configuration (a cloud download the game never gets here), so a save with a chosen bird skin stopped the load with a script error, and that error is what made the scene start over again and again. An empty configuration now exists, so the skin is simply not applied.
- **Stella: a scene is no longer entered again and again.** The menu manager takes a scene off its queue only after entering it, so while a level loaded (or when the entry stopped on a script error) another frame left and entered the scene again, over and over: hundreds of `GameScene:setupFrameElements()` lines and "attempted to add same listener twice" for each of the scene's listeners. The scene is now taken off the queue before it is entered, and an error in its entry is printed once. `AB_SCENEDBG=1` prints a stack for the first scene entries, `AB_LISTENERDBG=1` for each repeated listener.

- **Stella: resizing the window early.** A window resize before a level's camera limits were set (on a menu or the loading screen) stopped with `attempt to compare number with nil` in `forceScreenLimits`; the camera now leaves the view alone until the level has set its limits.

- **Stella: pupils and the other draw-call layers.** The pigs' pupils, the pig costumes' front and back layers and the other things Stella's scripts draw around an object (`native_setPreDrawFunction` / `native_setPostDrawFunction`, which the exe called as the object was drawn) were never drawn. The engine now calls them before and after the object's sprite, and a script can use `engine.drawObjectAfter(name)` for the same moment.

- **Replacing .apk and .ipa files:** dragging a mobile package onto the engine exe asks whether to play it, replace it or cancel; replace works like it does for an .exe and replaces the package with the engine under the package's own file name (the original is kept as `<name>.apk.original` / `.ipa.original`; dropping the package or the saved original on the engine puts it back). The engine is a Windows program, so the replaced package does not install on a phone or tablet.
* **The engine that replaces the retail exe looks like it.** Dropping an exe on the engine now copies the original's icons and version information into the replaced file, so Explorer shows the retail icon, and the window's title bar and taskbar button get it too (the small icon left of the game's name was missing because the icon was looked for in an exe that the engine had overwritten; the engine's own exe and the saved `.exe.original` are tried first now). A replaced exe is recognised by a mark in the engine instead of by being byte for byte the engine.
* **The saved `.exe.original` can be dropped on the engine** and puts itself back (it did nothing before, since it is not an `.exe`).
* **Command prompt and developer tools can be turned off.** `debugTools = false` in `config.lua` switches off the command prompt, the debug keys (as `AB_NODEBUGKEYS=1`), Ctrl + minus / plus and the Alt speed-up. The replace asks "Keep the command prompt and the developers' tools?" and writes the answer to `config.lua`; `--debug-tools on|off` answers it on the command line.
* **`console = false` no longer flashes a prompt.** The exe is a window program now and opens a command prompt only when one is wanted (`console = true`, the default, or `--prompt`); started from a prompt, it prints into that one. The prompt is opened before anything else is printed and its output and input are connected to the C streams (so every line, including the ones before the config is read, shows up), unless `config.lua` says `console = false` or `debugTools = false`.
* **Floating scores use the black-outlined font.** The 1.0.0 and 1.6.x PC scripts draw them with `FONT_INGAME_SCORE` (brown outline); the other releases use `FONT_SCORE`. The engine now uses `FONT_SCORE`; `floatingScoreFont = "FONT_INGAME_SCORE"` in `config.lua` brings the brown one back (`docs/USAGE.md`, "Options").
* **Finding what a level does by itself.** The console command `track <object>` prints an object's position and angle twice a second (a slow tilt reports no damage, so `AB_DMGDBG` stays silent), `track all` (or `AB_TRACK=all`) prints every object that moved or turned, and `AB_LOGFILE=<file>` sends everything the engine prints to a file.
* **The engine finds the game when it is started from another folder.** Run by its full path from a prompt that was opened elsewhere (or from a shortcut with no "start in" folder), it used to say it could not find `gamelogic.lua`; when the game is not in the working folder it now looks beside the exe.
* **Replacing an exe that is in use, and better error messages.** If Windows will not overwrite the exe (a copy is still running, or something holds it), the engine renames it aside, puts the new file in its place and deletes the old one (now or at the next restart). When it still fails, the message says why: protected folder (run as administrator), file in use, or the Windows error number.
* **Replacing an exe in Program Files asks for administrator rights itself.** When Windows refuses the write (a protected folder), the engine offers the normal "Run as administrator" prompt of Windows and does the job in that run, so the engine does not have to be started as administrator by hand. Windows' own permission is not bypassed, it is asked for.
* **Documentation:** the version, release and replace instructions were brought up to date.

## New in 3.8.1
* **The editor's joint window offers every joint the engine can make.** In the 1.6.x editors (Angry Birds 1.6.2 and the other games that use the built-in joint window) the joint-type button stopped at "Destroy-attached" and went back to "Distance". It now goes on to Pulley, Gear, Mouse, Line / Wheel, Friction and Rope (the joints 6 to 11 of `createJoint`) before it wraps; F6 to F11 pick them directly, as F1 to F5 pick the old ones. OK makes the joint with its defaults (see "Extra joint types" in `docs/SCRIPTING.md`) and it is saved with the level like any other. A gear couples the first revolute or prismatic joint of each of the two selected objects, so it needs one on each; without them OK makes nothing. This is part of the engine now (`joint_page.lua`), not of `extra_scripts.lua`.
* **The level spawner places a level, follows the game's order and draws the blocks' own pictures.** (1) **Placing:** a click on the level's picture shows the level as a half-transparent copy of its own pictures that follows the cursor (it has no body, so nothing collides with it, and the ground cuts it off as it does the real blocks); Return, Space or a click puts it down there, Escape goes back to the panel (`levelSpawner.placement = false` turns it off; Return in the panel still spawns at the cursor at once). (2) **The order the game loads them in:** folders and levels come in the order of the game's `levelOrder` (`levelOrder.packs` and `levelOrder[pack]`), so Level7 is the 9th level of pack1 and the panel says `1-9`; files that are not in the game's order follow, sorted by number. (3) **The picture uses the blocks' own images** (static blocks, which the game fills with the theme's texture, are bars; the giant Red Bird is maroon where a picture is not available). Blocks that stand turned (the thin ice and wood pillars) were drawn about the wrong point and missing from the picture; they turn about their middle now, and the picture and the copy match the level.

## New in 3.8
* **The level spawner is fixed and has a picture.** (1) Spawned objects are made the way the game's own level loader makes them: they are turned to their saved angle, get their material and the theme's texture (static blocks had none), their damage sprites, and pigs count as level goals. (2) The birds of the spawned level join the line-up: each gets the next start number, waits as the other birds do (static) and stands on the ground behind the last waiting bird (`levelSpawner.birds = false` leaves them out). (3) Up / Down walk through every folder of the `levels` folder that has level files (before, a folder was only found when it had a file with the same number), Left / Right through the files of the folder in number order, and `<`, `>`, `folder -` and `folder +` buttons do the same with the mouse. (4) The panel shows a small picture of the chosen level (`levelSpawner.preview = false` turns it off). (5) A dropped level file is read from wherever it is, the console says `spawned <file>` or `not spawned (not a level file?)` for each file that is dropped, and a drop while the panel is open closes it. New script function `listDataFolder(path)`.

## New in 3.7.3.1
* **The screen wipe is gone from the level editor of Classic 1.6.2.** Choosing a level on the editor's level pages, playing it from the editor (Shift+P) and coming back with the pause button or Esc still ran the wipe: the editor's level pages set the editor's mode before the level is loaded, and the way back loads the level while the play test is still the mode, which the check of 3.6 did not look at. The wipe now looks at the mode and at `startedFromEditor` when the level is loaded (`screenwipe.editor = false` brings the wipe back). Checked by loading a level with `startedFromEditor` set (no wipe starts) and without it (the wipe starts).

## New in 3.7.1 to 3.7.3
* **A save made right after a launch keeps the launch.** The copy of the running level that a save is written from was refreshed every half second, so leaving the level and saving soon after launching a bird kept the state from before the launch. It is refreshed every 0.05 s now; `saveStates.snapshotEvery` sets the interval.
* **Saved levels put birds back properly.** Six faults are fixed: (1) the object a variable points to (`flyingBird`, `selectedBird`, `cameraTargetObject`) was written under the wrong key, so a level saved while a bird was flying came back with no flying bird and the Blue Bird's tap did nothing; (2) a variable that was empty when the level was saved (the bird that is sent to the slingshot first) kept the value of the freshly loaded level, so the level's first bird jumped to the slingshot and took the place of the first bird; (3) the body type was not kept: the games hold the birds that wait as static bodies and make the next one dynamic, so a restored bird that was launched did not move (and a Blue Bird split in that state ended in an invalid position); (4) a level saved while the pieces of a split Blue Bird were flying stopped on `jumpTimer` (a nil value) after it was put back: the birds in `birds` that lack the animation timers get the value the games give to such pieces (9999); (5) the trail that is drawn lives in the engine, not in a script table, so it was lost; it is saved now (the dots and puffs of both trail sets), and `otherBirds` (the two pieces of a split Blue Bird, which the games record a trail for) is saved too, so every piece leaves a trail again; (6) the trail of dots (`birdTrajectory`) and `allowTrajectoryClearing` are saved, so the trail is still there. `getBodyType(name)` is the new counterpart of `setBodyType`. A save that is asked for (the leave pop-up, `saveStates.save()`) now says on the console when it keeps nothing and why (the level is finished or failed, the level is in `skipLevels`, it was not set up yet).
* **`console = false` in `config.lua`** closes the command prompt window that opens with the engine, so the game runs with only its own window (`true`, the default, keeps it; `--prompt` keeps it too).

## New in 3.7
* **Blue Bird split fixes:** when a level is restarted, the pieces of a Blue Bird that split (the one that is `flyingBird` first) move back to where the Blue Bird stood when the level loaded, like any other object. A saved level brings back birds that did not exist when it loaded, so split Blue Birds are kept instead of deleted, and `flyingBird` and the other saved references find them.
* **Level spawner (F1):** in a level, F1 stops the game and opens a picker: Left / Right choose another level of the folder, Up / Down another folder, Return (or a click on the panel) puts that level's blocks, pigs and joints into the level that is being played, around the cursor; Escape closes it. It is made the way the vehicles of Red's Mighty Feathers (3.3.0) are: every object is created with `createObject` under a new name (`levelSpawner.prefix`, a number and the old name) and every joint is tied to the new names. The ground and the birds of the spawned level are left out. A level file dragged onto the window while a level is played is spawned at the cursor the same way (`levelSpawner.drop = false` brings back loading it as the level). `levelSpawner` in `extra_scripts.lua` sets the key, the skipped definitions and the texts.

## New in 3.6

3.5 was published on GitHub; this section is everything after it.

* **A pop-up when a level that is half played is left (`extras/extra_scripts.lua`, section 7, table `exitPrompt`; the engine's `modalOpen` / `modalInput`).** The Menu button of the pause page and the back key ask first: S or Return (or the green button) leaves and keeps the state of the level, N or D (the red button) leaves and forgets it, Escape or C goes back to the game. While a script sets `modalOpen = true` the game gets no keys and no mouse and the script reads them from `modalInput` (`pressed`, `down`, `clicked`, `x`, `y`), so any script can show a pop-up. The music of a level is stopped in every menu.
* **Coming back to a level from the menu is a visit, not a restart.** The restart tween (objects moving back to where the level began) only runs for the restart buttons of the level itself; leaving to the menu forgets the level the restart was prepared for, and a level button never counts as a restart.
* **Hole blocks everywhere a block is made.** `createBox`, `createCircle` and `createPolygon` take a list of holes after their usual arguments (shapes in world units about the object); a block definition with a `holes` list (and, for a polygon, its `vertices`) gets them from `createObject`, from level files and from the editor with no other call. Level files that name `WoodBlock16` / `WoodBlock17` show the blocks (their sprites are cut before the level builds its objects, and the blocks are put back whenever the game loads its block table again). Making one no longer stalls the game: the cut pieces of a block are kept for the next one, the pieces are joined with a scan that only looks at neighbours, and the sprite sheet is decoded once for the five damage sprites.
* **The level editor is not wiped.** The screen wipe is skipped when a level loads while the game is in the editor and on the way to the editor page (`screenwipe.editor = false` brings it back). Ctrl+P in the editor of every game turns the physics on and off (`editorBehaviours = false` turns the key off), so blocks fall, take damage and run their script in the editors that have no key for it. The drag-selection box of Angry Birds 1.0.0's editor keeps its fractions of a unit instead of being cut to whole numbers.
* **The older joint call takes the newer joint types.** `createJoint(name, end1, end2, type, coordType, x1, y1, x2, y2, {groundX1 = ..., ratio = ...})`: a table after the nine values has the fields of types 6 to 11, so both ways of calling work side by side in every game, and a level can hold both kinds of joints.
* **The collision skin (`setPolygonRadius`, the console's `polyradius`) works in every game,** also on shapes that are already in the world; in Box2D 2.1.1 it is the skin the distance and time-of-impact code adds around a shape.
* **The bird rotation of the laser mod turns only the picture** (`setVisualRotation`), turns a bird back when it lands, and leaves the Boomerang Bird (`laserMod.rotateExclude`) and every bird whose definition has `rotateWhileFlying` alone.
* **Background shader: fewer state changes.** A run of quads that use the same shader and values sends the program and its values to the graphics card once (the heat-wave background drew every layer with a full program and uniform upload).
* **Save states are written only when asked for:** `saveStates.autosave` is `0` and the new `saveOnLeave` is `false` by default, so a level is kept only by `saveStates.save()` (the leave pop-up calls it); set them to get the old behaviour. `saveStates.skipLevels` (parts of level paths) still keeps chosen levels out of the save states.
* **Physics overlay in every game (key 8):** Angry Birds 1.6.2's overlay (sleeping objects in red, each block's collision shape in cyan and white, damaged blocks outlined in blue) is drawn by the engine in the games whose scripts have none, such as 1.0.0; 8 turns it on and off (`AB_NODEBUGKEYS=1` turns the key off).
* **Save states: Leave and keep saves the level as it was just before the pause page opened.** The state is copied in memory twice a second while the level runs (nothing is written), and `saveStates.save()` called while the level is not running (the pause page, a menu) writes that copy; before, it read the variables while the pause page had already changed the camera and other values.
* **Save states no longer keep the camera:** a level put back with its old camera (the `screen` table, the zoom, the camera function) opened with the view beside the slingshot; the game's own camera starts again now. `saveStates.tables`, `globals` and `cameras` can bring the camera back.
* **Save states: a bird put back is not asleep:** the bird waiting in the slingshot was put back asleep, and once launched it stayed where it was as if the physics were off; birds are put back awake now (blocks that were at rest still sleep).
* **Leave pop-up fix:** it opened only once per run of the game (the keys of the last pop-up were still in `modalInput` and answered the next one at once); it opens every time now.
* **Leave pop-up:** it now opens from the pause page's Level select and Menu buttons in every game (1.0.0 included; the two buttons are re-wired, the game's own press is made when the pop-up is answered), Back returns to the pause page, the level's music keeps playing on the pause page and stops when the level is left, and Leave and keep saves while the game is paused.
* **Documentation: adding and removing achievements** (`docs/SCRIPTING.md`), and `abAchievementTexts` for the how-to text of an added achievement.

* **Blocks with holes (any outline, holes of any shape at any position): `createShapeWithHoles`, `registerHoles`, the wood blocks `WoodBlock16` (a square with a square hole) and `WoodBlock17` (a wooden circle with three round cut-outs).** The hole is real: the physics body is made of the convex pieces that are left (`polydecomp::CutHoles` in `src/physics/polygon_decompose.h`: the outline and each hole are split into convex pieces, the hole is subtracted piece by piece and neighbouring pieces are joined again), so the mass is lower, a ball goes through, and the block collides along the edge of the hole. The outline can be a box, a circle (a 32-sided polygon) or any polygon, concave too, and a hole can be a box (with an angle), a circle or a polygon, fully inside, in the middle, across an edge or a corner (the top-left corner of a box, say), outside (it does nothing) or overlapping another hole. `createShapeWithHoles(name, sprite, x, y, outline, holes, density, friction, restitution, collision, controllable, zOrder)` makes one from a script (shapes in world units about the body's origin); `registerHoles(sprite, holes [, vertices])` gives every block that starts with that sprite its holes (shapes from 0 to 1 over the block), so a level file or `createObject` makes it with `createBox`, `createCircle` or `createPolygon` as before. `createPolygonSprite` takes the holes as a seventh argument and leaves them clear in the sprite, with the darkened edge along the hole as well. A block with holes counts the contacts of its pieces with another body as one hit. `docs/SCRIPTING.md` has the shape format; `extras/extra_scripts.lua` (section 5, `shapeBlocks`) takes `holes` in an entry; physics tests for masses, hole positions and the ball passing through are in `tests/physics_world_test.cpp`.

## New in 3.5

3.4 was published on GitHub; this section is everything after it.

* **Save states, in the engine, for every game: leave a level half played and come back to exactly that (`src/lua/save_states.cpp`, the Lua table `saveStates`).** While a level runs, its state is written to `savestates.lua` in the save folder every 5 seconds, when the level is left (the game mode leaves `updateGame`) and when the game is closed; loading the same level again (the key is the path it was loaded from) puts it back in the first frame the level runs, also after the game was closed and started again. Kept: every object of `objects.world` (place, angle, speed, at rest or not, and every number, string and flag in its table: strength, damage sprite, start number, ...), the script variables in `saveStates.globals` (the bird queue, shots fired, the score, the timers, the camera zoom), the tables in `saveStates.tables` (the score table, the camera), the objects `saveStates.objectGlobals` point to (the flying and the selected bird) and the camera function; what was destroyed is removed again (also from `birds`, `otherBirds` and `levelGoals`). A restart (a level loaded again within `saveStates.restartWindow` seconds of leaving it, or after `saveStates.forget()`, which the mod's restart button calls), finishing and failing a level clear the state. Objects the scripts made after the level began (the halves of a Blue Bird, debris) are not part of it. Everything is a field of the `saveStates` table that a script may change (`enabled`, `file`, `autosave`, `restartWindow`, `readyVariable`, the lists of variables, `skipWhen`), plus `save()`, `apply()`, `has()`, `forget()` and `clearAll()`; see `docs/SCRIPTING.md`. The variable names are the ones the games share (the Classic, Seasons, HD, Rio, Space and Star Wars game scripts all use the same bird queue and score variables). Checked on Angry Birds 1.6.2, level 1-1, with two separate runs of the game: in the first a Red Bird was removed, two blocks given 3 and 5 strength, a block moved, a damage sprite set and the score table set to 1234; in the second, started from nothing, the log said the state was put back and the blocks had their strength and sprite, the bird was gone and the score was 2334 (1234 and the 1100 of the weak block that then broke); leaving to the menu wrote the state; a restart left no state to put back. Not yet tried in the other games.

* **Hooks for the remaining Box2D joints: `createJoint` types 6 to 11 (pulley, gear, mouse, line / wheel, friction, rope).** The game editors only know distance, weld, revolute, prismatic and the destroy-attached link (types 1 to 5); the other joints Box2D has can now be made from Lua with the same call, take their fields from the table, write `objects.joints[name]` and can be changed with `setJointParameters` (gear ratio, mouse target / force, friction limits, motor and limits of the line / wheel joint). The line joint exists in the bundled Box2D 2.1 (Classic, Seasons, Space), its successor the wheel joint (with a suspension spring) in 2.2 (Rio, Star Wars, Friends); type 9 makes whichever the game's Box2D has. The rope joint is new to 2.1: Box2D 2.2 has it, and it was back-ported to the bundled 2.1.1 (`b2RopeJoint`, same solver as 2.2.0 written for the 2.1 joint interface, marked as an altered version in its source), so type 11 works in every game. A gear joint is destroyed together with either joint it couples (including when a body is removed), the mouse joint pulls against a fixed body made on first use. Reference and an example in `docs/SCRIPTING.md`, "Extra joint types". Checked with new tests on both Box2D versions (a pulley lifts the light side, a gear carries a hinge's rotation, a mouse joint brings a body to its target and moves it when the target changes, a line / wheel joint keeps the body on its axis, a rope stops a falling weight at its length, removing a gear's base body leaves no joints behind) and on level 1-1 through Lua (`createJoint{type = 8, ...}` moved a wood block from y = -11.21 to the target -15.21 and lifted the pig tower with it).

## New in 3.4

3.3 was published on GitHub; this section is everything after it.

* **Release tooling and documentation: `publish.bat`, `make_release.bat <version> [publish]`, `docs/RELEASING.md`.** `publish.bat v3.4 "what changed"` builds, runs ctest, checks (with `git grep` over every file git would commit) that the Windows user name is nowhere in the files and that git has an author e-mail, commits, pushes and makes the GitHub release with `gh`; without the message it only builds, tests and checks. `make_release.bat` takes the version (it was fixed at v3.1), writes the release notes from the version's `## New in` section of this file to `release-notes.md`, and with `publish` runs `gh release create` with the zip. `docs/RELEASING.md` has the one-time setup (tools, `gh auth login`, a commit identity that is not yours, the remote), each step by hand, and a table of what to do when a step stops.

* **Fix: TNT crashed with the gravity zone (`removeBlocks: attempt to compare nil with number` in `makeExplosion`).** The game's explosions go through everything in their radius and compare its `strength` and `defence`; the zone's sensor circle has neither (it is not a block), so a TNT near the zone raised a script error (first seen on level 2-20). The mod now gives the zone `strength` and `defence` of 1e9. Reproduced on level 1-1 with a TNT next to the zone (error with the mod, none without it or with the zone off; none with the fix, the TNT explodes and scores).

* **Concave and large polygons everywhere, a no-limit shape cast, and star / wedge / chevron wood blocks.** (1) *Physics:* `createPolygon` (and the polygon parts of compound objects) used to give Box2D a concave outline as it was (it made the convex hull) and cut an outline of more than 8 points into a fan from the first point (right only for convex shapes). A concave outline is now split into the fewest convex pieces of at most 8 points (`src/physics/polygon_decompose.h`: ear clipping, then Hertel-Mehlhorn merging), one fixture each on the one body; convex outlines keep the old paths, so existing levels are unchanged. Checked: a 10-point star of outer radius 2 / inner radius 1 and an L of area 7 get masses 5.878 and 7 (their real areas), a cast into the notch of the L hits the arm and not the hull. (2) *Shape cast:* the 8-vertex cap is gone, `{points = ...}` takes any convex or concave outline (up to a few hundred points; each convex piece is swept with the time of impact, the earliest touch counts) and `{sides = n}` goes to 128. A T-shaped caster sent down at a star stops with its spike tip on the star's top point (y = -35.075 for a tip 3 below the centre and a star top at -32). (3) *`createPolygonSprite(newName, source, points [, outline [, darken [, fill]]])`:* a copy of a sprite cut to a polygon (anti-aliased, optional darkened edge, optional fill of the source's holes). (4) *Shape blocks (extra_scripts version 16, section 5):* `WoodBlock13` (star), `WoodBlock14` (wedge) and `WoodBlock15` (chevron) are registered in `blockTable.blocks` as polygon blocks with their own cut sprites for the four damage stages, and the wood group's `lastIndex` is raised for the editor's keys; add your own in `shapeBlocks.blocks`. Spawned over level 1-1 they fall and come to rest on their real edges (the star on two points, the chevron on its legs).

* **Shape cast: `rayCast` takes a shape (new `ShapeCastAll` in the physics), and the laser is an octagon.** `rayCast(x1, y1, x2, y2, all, shape)` with a `shape` table (`{radius=}`, `{sides=, radius=}`, `{w=, h=}` or `{points={...}}`, plus `angle` and `skip`; see `docs/SCRIPTING.md`) sweeps that shape along the segment instead of a bare ray. Box2D has no shape cast, so it is built from `QueryAABB` over the swept area and `b2TimeOfImpact` against each fixture (the bundled 2.1 solver reports only `t`, the 2.2 one a state; both are handled); the hit comes with the centre of the shape at the moment of contact (`cx`, `cy`), the contact point and the normal. Without `shape` nothing changes. Checked on level 1-1 with a horizontal cast at a plank column: ray hit at x = 39.47, circle of radius 2.5 stops with its centre at 36.92, an octagon of radius 2.5 at 36.82, a 5 x 5 box at 36.82. In `extras/extra_scripts.lua` (version 15) the laser is now an octagon the size of the bird (`laserMod.shapeSides = 8`, `shapeRadius`, nil = the bird's own radius; `shapeSides = 0` gives the old thin ray), so it is stopped by rock and immovable things at the width of the bird, and it **eases in to the cursor position cached when it fires**: the head travels there in `laserMod.beamTime` (0.15 s) with `laserMod.beamEase` (`"inCubic"`), and whatever it crosses is hit as the head passes it.

## New in 3.3

3.2 was published on GitHub; this section is everything after it.

* **Fixes to the laser mod, and the restart.** (1) *Objects stayed violet:* the zone's tint is a render override that belongs to an object's **name**, so an object that was destroyed, or whose level was left or restarted while it was inside the zone, kept the tint, and the next object with that name (every level has `RedBird_4`) came up violet. The mod now remembers which objects it tinted and takes the tint off when the object leaves the zone, is removed (`objectRemoved`), or a level loads (`levelLoaded`, which a restart also raises). Checked: restart pressed while the bird was inside the zone, the tint of the bird and of the next bird is back to normal after the reload. (2) *Only a restart rewinds:* the check was too loose; the menu item that was used last can be a restart button that is still selected when another level is picked. A restart is now only a load of the level that the snapshot is of (`levelFolder` and `levelName` equal), so picking another level, next level and the level select change at once, as before (checked: another level name loads with no rewind). (3) *Ease in only:* the rewind of the objects used `inOutCubic`, a speed that rises and falls like a bell; `levelRestart.ease` is now `"inCubic"` (slow at first, fastest at the end); any easing or function can still be set.
* **The engine exe can replace another exe (drag-and-drop, `--replace-exe`, `--restore-exe`).** Dragging a game's `.exe` (or any `.exe`) onto the engine saves the original as `<name>.exe.original` and copies the engine over it, after a question; dragging the replaced exe on the engine again puts the original back. See `docs/USAGE.md`, "Replacing the game's own exe with the engine". Tested here with a stand-in file: replace (original saved byte for byte, target identical to the engine), second drop restores it, missing file, no backup to restore and the exit codes.
* **The aiming aid bends inside the gravity zone (new global `aimGravityZones`).** The aiming aid's arc is the bird's free flight in a scratch world; it did not know about a script's sensor zone, so the dots flew straight on while the real bird curved. `simulateAimingAid` now reads the global `aimGravityZones`, a list of `{x =, y =, r =, gx =, gy =}` (round areas, at most 16, physics units), and inside one of them the simulated bird accelerates by `gx, gy` instead of the world's gravity, from the step after it touches the circle (its own radius counts), as `setObjectGravity` does for the real bird. The laser mod publishes its zone there every frame (the right-click move included). Tested on level 1-1 with the shot that crosses the zone: the real bird's y against the aid's y at the same x differs by 0.1 to 0.2 units up to x = 16 (with the zone ignored it was 0.3 to 2.3, and 5.6 at x = 25), and the dots in the screenshot flatten inside the zone.
* **Restart in `extras/extra_scripts.lua` (version 14, section 4).** The restart button (in the level, in the pause page and on the end-of-level pages) no longer reloads at once: the objects that are left tween back to the places the level began in (written down in the first game frame; `motion.to`, 0.8 real seconds, `inOutCubic`), and only then is the level restarted, with **no screen wipe**. The entrance to a level and every other wipe are unchanged (checked: entering a level still runs the wipe timer 0 to 1, a restart leaves it at nil). Objects that were destroyed come back with the restart itself. Settings in the new `levelRestart` table (`enabled`, `time`, `ease` (any easing of the `motion` library, or a function), `minDistance`); `screenwipe.skip` is the new switch the wipe checks. How the restart is found: the button inside a level calls `setGameMode(updateLoading)` itself, the menu buttons do the same for an item with `restartLevel = true`; the call is held back until the objects are home (a second click meanwhile is ignored). Tested on level 1-1: after a shot that knocked the tower down, a click on restart moved the planks, ice and birds back (a screenshot half way shows the tower going up again), the score stayed until the reload, then the level came back with score 0 and no wipe.
* **Every bird turns to face its flight (laser mod), and the gravity zone no longer stops it.** The rotation is no longer for Red Birds only: a bird is anything whose definition says `group = "birds"` or whose name or definition has "bird" in it, in any game; a definition with `rotateWhileFlying = true` (Blu in Rio, which the game turns itself) is left to the game. The turning stopped when a bird entered the anti-gravity zone because the `contact` event also reports sensor contacts, which counted as a landing; contacts with `zone_` objects are now ignored. Tested with a Yellow Bird through the zone: its angle follows the flight direction before, inside and after the zone. The laser is still for Red Birds (`laserMod.birdNames`). Also fixed in `motion.lua`: a job whose objects were all removed now counts as done (its `onDone` runs), so a restart cannot hang when a plank is destroyed during the tween; needs a rebuild.
* **The rewind can be shaped, and any movement is possible (the `motion` library).** Tested first: `rewind(20)` works (20 frames after its launch a bird was back at the slingshot's pulled-back position). New natives `getRewindDepth()`, `getRewindState(back)` (every body's x, y, angle, speed and spin that many frames ago) and `setRewindLimit(frames)` (the history is no longer fixed at 600 frames; 0 turns it off). On top of them `src/lua/motion.lua` (embedded, loaded into every game before its scripts):
  * `motion.to` tweens objects with any easing: every Penner family in, out and inOut (quad, cubic, quart, quint, sine, expo, circ, back, elastic, bounce), CSS bezier curves, steps, springs, or your own function; along a point list (smooth line) or a `path` function of your own; with delay, loop, yoyo, a different easing per axis, and `release = "throw"` to hand the tween's speed to physics.
  * `motion.drive` runs a function every frame (homing, orbits, following the mouse); `motion.teleport` moves at once; `motion.stop`, `motion.stopAll`, `motion.isMoving`.
  * `motion.rewind` / `motion.rewindObject` play the history back as a movement whose speed profile is an easing function (soft, bouncing, there and back), for all or chosen objects, backward or forward (`from` / `to` history frames), keeping the old speed at the end.
  * Tests on level 1-1: a plank went exactly 8 units up with `outBounce` (onDone fired), a pig followed a sine `path` function, a bird was teleported, a flying bird was rewound 40 frames with `outBounce` and flew on from its old state; the CSS `ease` bezier gives 0.8024 at 0.5, as the spec does. See `docs/SCRIPTING.md`, "The history and the `motion` library".
* **The laser mod in `extras/extra_scripts.lua` (version 13, section 3).** It is part of Classic 1.6.2's extra script. Three effects, each with its own switch in the new `laserMod` table (`laserMod.laserBird`, `waveShader`, `gravityZone`; every number can be changed from the console, e.g. `lua laserMod.damage = 50`):
  * **Laser Red Bird.** Tap (or press SPACE) while a Red Bird flies: the physics slow down (`laserMod.slowFactor`, 0.25) for 0.6 real seconds, a red laser with a white core is drawn along the bird's direction, and everything the ray crosses (`rayCast` with `all = true`) gets an impulse along the beam and loses `laserMod.damage` strength. The game itself then destroys what reached 0, so the score, the floating numbers and the particles are the real ones. Tested on level 1-1: the laser killed the pig behind the tower (score 5000, puff of smoke) and took 25 strength from the planks on its line.
  * **Heat-wave shader.** A GLSL shader of your own, `heatwave`, created with `createShader` on every level load and set on the target `"background"`: the picture shimmers sideways and goes slightly blue, and the strength breathes with a sine. `laserMod.waveShader = false` turns it off again at once (the background goes back to normal).
  * **Anti-gravity zone.** A sensor ball (`zone_vortex_1`) made 20 units in front of the slingshot in the first game frame of every level (the slingshot position is not known when `levelLoaded` is raised). A body that flies in gets its own upward gravity (`setObjectGravity`, 15 units per second squared) and a violet tint until it leaves; a counter per body makes the two fixtures of one object count once. An outline of the zone is drawn. Other scripts' `enterCollision` / `exitCollision` are still called.
  * **Changes after the first version of the mod:** (1) the heat-wave now moves the sky as well: the sky is a picture that only changes from top to bottom, so a sideways shimmer was invisible on it; the shader now also shifts the picture up and down (`laserMod.waveAmplitudeY`, 6 pixels, breathing like the other). (2) A right click anywhere in a level moves the anti-gravity zone to the cursor (`keyPressed["RBUTTON"]`, `cursor`, `screenToPhysicsTransform`, `setPosition`); a body that is inside when it moves is released through `exitCollision`. (3) The laser breaks every object whose material is in `laserMod.breakMaterials` (`light`: ice and glass) at once, and `laserMod.push` is now a speed (30) that is multiplied by the object's mass, so a heavy plank is pushed as far as a light one. Tested on level 1-1: both ice blocks under the tower are gone after one shot, the planks on the line are thrown and the tower collapses.
  * **Second round of changes:** (1) the laser now goes from the bird to the cursor (to where you tapped; with SPACE, to where the mouse is) instead of straight along the flight, at most `laserMod.maxRange` (1000) physics units; it falls back to the bird's own direction if the cursor is on the bird. (2) Rock (`laserMod.blockMaterials`) and everything that has no mass (the ground, the "immovable" planks) stop the beam: it ends at the point where it hits them, and what is behind is not touched; the sensor zone is still passed through. (3) A Red Bird now turns to face its direction of flight from the launch until it first touches something (`laserMod.rotateBirds`; the `contact` event ends it). (4) The top of the screen did not match the rest of the sky: above the sky picture the game shows its clear colour, which the shader's blue tint never reached, so a strip of the old colour stayed. The mod now draws that colour first, under the layers, with the same tint (`laserMod.waveTint`, also read by the shader through `setShaderParam` slot 1). A flat colour has nothing to shimmer, so only the colour is the same there. Checked by pixel: the strip and the sky below it differ by 2 of 255.
  * **What was wrong in the original file, and is fixed:** `setPhysicsSimulationScale` does nothing in this engine (slow motion is the global `physicsSpeedFactor`, which is now saved and restored), and in Classic it is set to 20 by the game, so the file's `setPhysicsSimulationScale(1.0)` would have been wrong anyway; `destroyObject` does not exist in Classic (the game removes objects whose `strength` is 0 or less by itself); `createCircle` has 10 arguments in Classic, the file gave 11 (the extra `false` became the z order); the beam hit the ground, whose strength would have run out after two shots; a tap was counted for the whole time the finger stays down, so now only the press fires; the zone was made in `levelLoaded`, where the slingshot is still at 0, 0; and the beam and the zone were placed with `* 20` and the camera by hand, the game's own `physicsToScreenTransform` is used when it exists.
* **The layout of what the engine draws itself can be changed from Lua.** Until now the natively drawn backgrounds, foregrounds, trajectory dots and the aiming aid could be styled (tint, blend mode, shader presets, blur ...) through the targets `"background"`, `"foreground"`, `"trajectory"` and `"particles"`, but not moved or resized. Four new functions take the same targets as the graphics settings of 2.4 (those four, an object name, a sprite name or a composite sprite name) and keep the setting for that target, so every later draw of it uses it:
  * `setOffset(dx, dy, target)` moves everything of the target by `dx`, `dy` (in the pixels it is drawn in; for the trajectory dots, the aiming aid and objects these are world pixels, so they follow the camera zoom). `getOffset(target)` returns the two values.
  * `setLayoutScale(sx [, sy], target)` makes every sprite of the target `sx` times as wide and `sy` times as high (`sy` is `sx` when it is left out), each about its own centre: the trajectory dots grow in place, a background layer grows about its middle.
  * `setLayoutScale(sx, sy, px, py, target)` scales positions as well, about the point `px`, `py` shared by everything of the target, so a whole group grows or shrinks as one (the foreground 1.6 times as large about the middle of the screen; the dots spread apart and grow).
  * `setMirror(true, target)` draws the sprites of the target mirrored left to right (`false` puts them back).
  * `resetRenderOverrides(target)` now forgets the layout as well. A target is required (without one the functions do nothing, since there is no render-state value to change for them).
  They work for every game (Classic, Seasons, Rio, Space, Star Wars, Friends, Stella and the HD and Android data). The anchors of a sprite (centre, pivot, bottom edge ...) are resolved first, so that offset and scale act on the sprite's top left corner and size alone; the setting comes after the engine hook `engine.drawSprite`, so a hook's `dx`, `dy`, `sx`, `sy` and a target's layout add up. Examples: `setOffset(0, 120, "background")`, `setLayoutScale(1.6, 1.6, 640, 360, "foreground")`, `setOffset(-60, -40, "trajectory")`, `setMirror(true, "foreground")`.
  Tested in Angry Birds 1.6.2: the sky moved down 120 pixels with a red tint, the trajectory dots moved up 80 pixels and turned red with the foreground moved down 80, and the foreground scaled 1.6 times about the screen centre and mirrored. Screenshots: `shots/layout_background_offset.png`, `shots/layout_trajectory_foreground_offset.png`, `shots/layout_foreground_scale_mirror.png`.
* **Shaders written in GLSL, every preset editable, and a shader creator.** `setShader` used to have only six built-in presets (none, grayscale, sepia, invert, chromatic, glow) because the renderer was fixed-function OpenGL 1.x. The OpenGL backend now also loads the OpenGL 2.0 shader functions (`glCreateShader` ... through SDL, like the rest) and compiles your own fragment shaders. Where the driver has no shaders, or with `AB_NO_SHADERS=1`, or in the CPU renderer that tests use, nothing changes: the presets work as before and a custom shader is reported as unavailable.
  * **A shader is a file**, `<user data folder>/shaders/<name>.frag` (the folder given with `--userdata`, else the working folder). It defines `vec4 shade(vec4 texel, vec2 uv, vec4 tint)`; the engine puts a prelude in front of it with `u_tex`, `u_time`, `u_texel` (the size of a sheet pixel), `u_resolution`, `u_hasTex`, `u_uvRect`, `u_param0` .. `u_param3`, `v_uv`, `v_color`, `v_pos` and `sampleTex(uv)`, and adds the `main()`. A file with its own `void main` gets the prelude only, so a complete fragment shader can be written too. Error lines refer to the lines of your file.
  * **Use it** with `setShader("name" [, target])` on the same targets as every other graphics setting (an object, a sprite, a sprite group, `"background"`, `"foreground"`, `"trajectory"`, `"particles"`), or as the 21st value of `setRenderState`. `setShaderParam(name, slot, x [, y, z, w])` sets `u_param<slot>` (slot 0 to 3).
  * **Without a file**: `createShader(name, source)` compiles a shader from text in a script and returns `true` or `false, errors`; `getShaderError(name)` and `listShaders()`.
  * **All the presets are shaders now, and editable.** `shader export` (console) writes `grayscale.frag`, `sepia.frag`, `invert.frag`, `chromatic.frag` and `glow.frag` (and the other templates) to the shaders folder, without touching a file that already exists. From then on `setShader("grayscale")` and the others use the file, so a preset is changed by editing it; delete the file to get the built-in one back.
  * **Live reload.** The files of the loaded shaders are watched twice a second; saving one compiles it at once and the picture changes without a restart. A mistake prints the compiler's messages (`shader <name>: ...`) and the last version that worked keeps running.
  * **The shader creator, in the console**: `shader templates` (blank, grayscale, sepia, invert, chromatic, glow, wave, scanlines, vignette, pixelate, pulse), `shader new <name> [template]` (writes `<name>.frag` from a template and loads it), `shader apply <target> <name>`, `shader param <name> <slot> x [y z w]`, `shader check <name>`, `shader reload [name]`, `shader list`, `shader export`. The old `shader <object> <effect>` still works.
  * **A shader sees one sprite at a time.** `sampleTex` is held inside the sprite's own part of its sheet (`u_uvRect`), so a blur, glow or distortion never picks up the next sprite, and an effect cannot draw outside the sprite's rectangle (the built-in presets 4 and 5 drew copies outside it; the glow template stays inside). A sprite's tiled ground blocks (masked quads) use the fixed pipeline and are not shaded.
  Tested through the OpenGL path in Angry Birds 1.6.2: a hand-written rainbow shader on the background (`shots/shader_custom_rainbow_glsl.png`); the grayscale preset edited to a blue tint, and a second shader on the foreground that was saved while the game ran and changed green at once (`shots/shader_edited_preset_and_hot_reload.png`); a compile error shown with the right line numbers; `shader new/export/list/check/param/apply` and the vignette and pixelate templates applied from the console (`shots/shader_console_apply_vignette_pixelate.png`); all 11 templates compile.
* **`--decrypt` no longer hangs on scripts that unluac repeats for ever.** Some compiled (stripped of debug information) scripts send unluac 1.2.2 into a loop in which it writes the same text for ever: Seasons 4.1.0's `scripts/menu_flow.lua` produces `[#{ [#{ [#{ ...` until the disk is full. `--decrypt` waited for it without a limit (on Windows there was no limit at all), so the second decompiler (`tools/unluac-alt.jar`, which finishes this script in under a second) was never tried and the run never ended. Each try now has a time limit (**90 seconds**, `AB_DEC_TIMEOUT=<seconds>` changes it, `0` means no limit): when it runs out the decompiler and everything it started is killed (a Windows job object, or a process group on Linux), the console says `dec: <jar> gave up after N s on <file>`, and the next decompiler tries the script. The alternative decompiler beside the jar named in `AB_UNLUAC` is tried too. A script that no decompiler finishes is listed as not decompiled and the game keeps using its compiled copy, as before. Tested on `menu_flow.lua` from Seasons 4.1.0 for PC: unluac 1.2.2 gave up after 10 s (`AB_DEC_TIMEOUT=10`), unluac-alt wrote the 200-line text.
  Note on what that text is: a script stripped of debug information has lost its local variable names, so the alternative decompiler names the registers `L0_2`, `L1_2` ... and writes every step on its own line (the original structure is all there, the names are not). Nothing can bring the original names back; an AI model cannot be built into the engine, but this output can be read and renamed by hand (or by asking me to tidy a particular script).
* **Fixed a crash when a level is loaded from the update script (Angry Birds 1.0.0: clicking level 1-8, `exception 0xc0000005`).** At the end of every frame the engine calls the game's Lua `update`; in 1.0.0 that call can start a level (`loadLevel`), and starting a level builds a brand new physics world and frees the old one (`BeginLevelLoad`, 2.2). The frame function (`UpdateFrame`, `src/game/frame_update.cpp`) then still read the old world's `running` flag, one byte of freed memory, to decide whether to update the effects. On Linux that read happened to see the old value; on Windows the freed block had been reused and the read crashed (`The game crashed: exception 0xc0000005 at ...`). It is now read before the update call (the effects are the same: they only run when physics ran at the start of the frame). Found with valgrind on the level load (`Invalid read of size 1 ... free'd by BeginLevelLoad`), using the save and the level files of the report; no other invalid read was reported on the way into the level.
* **Documentation.** `docs/SCRIPTING.md` ("Graphics settings for one target") lists the four functions; the README's list of limits no longer says that the layout is not editable (shader programs written in GLSL are still not possible with the OpenGL 1.x renderer).

## New in 3.2
* **Angry Birds HD 1.4.2: the menu balloons sway at the phone's speed at any frame rate.** The balloons that rise behind the main menu (the Danger Above reward sprites, `reward == 2` entries of `birdAnimations`, moved by `animateBirds`) sway sideways by `x = x - angle * layer / 2` on every update, a step with no time in it, so with the frame rate not limited the sway distance grew with the frame rate and the balloons swung far across the screen. The sideways step is now scaled by the frame's time and taken `abPictureRate` (30) times a second, exactly like the Friends shine below (`animateBirds` is wrapped once in `abFrameSteps`; the speed-and-time move `x += xVel * dt` is left untouched). Checked by running 20 seconds of simulated updates at 20, 200 and 2000 frames a second: the sway range is 4.62, 4.76 and 4.78 units, where before it grew in proportion to the frame rate. Screenshot: `shots/hd142_balloon_sway.png`.
* **Friends: the shine fix is the same mechanism.** The shine behind the buttons (`GlowImageButton`), the gift rays and the light beams were already scaled by the frame's time in 3.1; the balloon fix reuses that scaling (`abFrameDt * abPictureRate`, at most 6 steps per frame) and the same `AB_PICTURE_RATE` setting.
* **Release note.** The last version published on GitHub was 3.1. 3.2 is not published yet, so everything in this section, from the debug-console and Stella fixes to this balloon fix, ships together in the 3.2 release.

* **Saves with a NaN in them are read again, and none are written any more.** A number that is not a number (NaN) was written as Windows prints it, `-nan(ind)`, which Lua cannot read, so the whole file was set aside as `settings.lua.corrupt` and the game started over: Friends 2.0.0 lost its progress this way (its main menu keeps a zoom value that is 0 / 0 when the theme's layers have no scale entry). NaN is now saved as `nil` (what the phone's `nan` read as) and infinity as `1e999`, and a file an older build wrote with `-nan(ind)`, `nan`, `inf` or `1.#INF` is read with those values replaced, so `settings.lua.corrupt` can be renamed back to `settings.lua`.
* **Friends 2.0.0: the menus and the Rovio News card follow a resized window.** The phone's screen never changed size, so a page kept the size it was built at (the main menu sets its width and height once); a resized or maximised window left the main menu laid out for the old size. Pages built at an earlier window size now take the new size before the game lays them out again (when the size changes and when a page is shown). The Rovio News card in the pause menu is sized from the space the pause page gives it (7:5, its text scaled with it), and that space moves with the window.
* **Friends 2.0.0: Friends 1.0.0's tournament levels in the Weekly Tournament.** The `.apk` ships no tournament levels; the engine now copies Friends 1.0.0's 30 tournament levels (`levels/pack57`) to `data\levels\friends_1.0.0` from a Friends 1.0.0 `.ipa` it has unpacked or one beside the `.apk`, and the tournament plays six of them a week. Level files in `data\levels\tournament` replace them (the 1.0.0 levels are used only while that folder has none).
* **Space and Star Wars: background elements wrap as in the exes.** The planets, clouds and asteroids the scripts scatter (`createThemeSprite`) never wrapped. **Angry Birds Star Wars: the engine now follows the retail exe's physics and per-frame update.** Everything below is ported from the decompiled `AngryBirdsStarWars.exe` (addresses in brackets); the modding side of it is in [`docs/SCRIPTING.md`](docs/SCRIPTING.md#angry-birds-star-wars).

* **Contact filter and object flags (0x410e70).** Star Wars has its own rule for which two objects collide: collision groups (`setCollisionGroupIndex`, parameter 36), per-object material lists, kind 7 objects that never collide with each other and parameter 19 as the exception. The natives that set one flag of an object record (`setBlockCollisionEnabled`, `setIgnoresScore`, `setKeepOrientation`, `setAffectedByForceMultipliers`, `setIsWater`, `setWaterDensity`, `setControlled`, `setTimeSinceCollision`) are real now, not no-ops.
* **Water (0x41e440, 0x423270).** A gravity sensor flagged with `setIsWater` is a pool: boxes push up and circles pull towards their centre with a force that fades over the top 1.5 world units, with extra drag for birds (`setBirdWaterDrag`, 0.4) and objects (`setObjectWaterDrag`, 0) and a force multiplier for fresh birds (`setWaterForceMultiplier`, 2).
* **Collision damage (0x42f9d0).** Star Wars no longer runs the older games' damage rules. Forces divide by 10 after the config's `forceDamageMultiplier` (1); a bird hitting a block uses the momentum difference of the two (bird scaled by its damage multiplier and `powerupDamageMultiplier`), a HOMING bird that has not collided yet does a fifth of the damage, a block that dies takes the bird's velocity (at once with `useLegacyCollisionPath`, after the step otherwise) and the contact is switched off; two blocks take `force * factor - defence` (strength drops by the floor of it), `ignoresScore` objects score nothing, and the score added is `floor(damage) * scoreDamageMultiplier` followed by `addScoreToBird`. Damaging sensors (kinds 5, 6 and 7, unless the other object has parameter 20) hurt blocks with their definition's `damage`. `birdCollision` now receives `(a, b, force, damage, pointX, pointY, normalX, normalY)` and `blockCollision` `(a, b, force, wasDamageDone, false, damage, pointX, pointY, normalX, normalY)`, which the scripts' damage particles and collision actions read (they used to get nil). The first collision of a bird starts its gravity timer.
* **Hit wobble (0x42fe61).** Blocks with a `bounceAmplitudeMultiplier` (parameters 6 and 7) wobble when hit: the amplitude is `min(force * 0.02, 0.1)` and the phase of each object is shifted by its place in name order times a quarter turn. Two birds that collide start the same wobble unless an object has parameter 11 set.
* **End of contact and kill timers (0x41f370, 0x433464, 0x433771).** When a contact ends both bodies are woken, `exitTriggerCollision` fires for sensors (the sensor bookkeeping runs its exit side) and `exitCollision` always fires. A kind 4 sensor touched by a non-sensor, and an object with `stopOnExit` (parameter 34) leaving a flagged sensor, get a kill timer that the frame update counts down and then destroys the object. Sensors of kind 5 and 7 that drift beyond 0.88 times a level limit are removed straight away.
* **Per-frame object sync (0x433500).** `hasMovingObjects` ignores joints and any object with parameter 12 set and tests the absolute spin; `hasMovingObjectsZeroTolerance` is published (anything but a controlled object that moves at all); every awake object gets `objects.world[name].velocity` (the speed), which the scripts' specialty speed limit and drag threshold read; objects with the material `propeller` (and any object after `setRecordVelocity`) publish `xVel`, `yVel` and `angle` like birds do. Objects with parameter 9 (enable flipping) turn to face their direction of travel by calling parameter 8 each time they move faster than 3 sideways.
* **`createLineShape` (0x439640).** A body made of edge shapes, one for each pair of neighbouring vertices from `clearVertices` / `addVertex`, with the same arguments as `createPolygon` (Box2D 2.2 builds). The world entry has `type = "line"`. The retail game only uses it for the editor's `STREAM_1` block, but mods can use it for thin, one-sided or open terrain.
* **Aiming aid.** `populateAimingAid` (0x402770) lays the dots out along the stored trajectory, as the Space one does; the trajectory itself still comes from `updateBirdTrajectoryTable`.
* **`renderGravityVisualsNative` (0x415f90)** is implemented: circle sensors draw each entry of their `gravityVisuals` list eight times around the sensor and box sensors draw bars along their length. The game's own script calls it with three arguments, the exe reads the missing fourth (the zoom) as 0, and the retail game therefore draws nothing; the same happens here. A mod that passes the zoom as fourth argument gets the rings.
* **Level joints keep their fields.** `createJoint` stored only the values it used on `objects.joints[name]`, so a level-select scene (Endor, Death Star 2) lost `isDrawn`, `breakable`, `breakForce`, `jointPosX` and `jointPosY`; the retail scripts read them to draw vines and ropes (`gamescene.lua`) and to decide which joints break. They are kept now. `AB_JOINTDBG` also logs how many entries each `createJoints` call got, and `AB_DUMPLEVEL=<prefix>` writes one file per loaded level (`<prefix>.<level>.lua`).
* **Star Wars foreground layers (0x44b9xx).** With `NEW_THEME_SYSTEM_FOREGROUND` the theme's `fgLayers` only go through the new-system routine; the old positional/named foreground loop used to run as well, so Cloud City's foreground was drawn twice. Without the flag only the positional loop runs, and its fourth entry (scale) defaults to 1, not 1.5.
* **Stale joints after a tap.** `removeObject` clears `objects.joints` entries of the removed object in Space and Star Wars too (tapping a log or pig in a level select no longer leaves a joint pointing at a missing object, which stopped the draw loop before the buttons and cursor).
- **Angry Birds Seasons 4.1.0 start-up.** The scripts read the globals `uniqueInstallationId` (settingsWrapper.lua) and the table `native` (createStartUpAssets); both exist now (as bare globals and in `_G`, the real global table, which is where createStartUpAssets looks: `_G.native`), so the game no longer stops with "attempt to concatenate global 'uniqueInstallationId'" / "attempt to index field 'native'".
- **Seasons 4.x start-up (2).** The scripts call `requireFile("Scaling.lua")` and similar, both as `_G.requireFile(...)` and by bare name; the engine now has it (runs the file once, looked up in the game's script folder and then `commonScriptPath`). A Seasons build whose config has `commonScriptPath` is no longer treated as Star Wars / Space (no Star Wars physics, no Space natives): it runs `scripts_common/gamelogic.lua` and the rest of the Seasons start-up as a Seasons game.
- **Backgrounds and foregrounds from Lua.** `getCamera()`, `getThemeLayers()` and `setThemeLayer(index, fields)` give the theme layers as data (`dx` and `dy` move a layer in screen pixels, `hidden`, `speed`, `scale`, `sprite`, `offX`, `offY` and more), `engine.on("drawBackground" / "drawForeground")` (and the `...Before` versions) let a script draw its own layers, and `tuning["background.skip"]` / `tuning["foreground.skip"]` replace the engine's drawing entirely. `docs/SCRIPTING.md` has recipes for sine-wave parallax.
- **Rule hooks.** `engine.shouldCollide(a, b)` lets Lua decide whether two objects collide (every game), and `engine.strengthChange(name, other, old, new)` lets Lua replace the strength a block is left with after a hit. `engine.tuningDefaults` lists every `tuning` name with its default.
- **Drawing and damage hooks.** `engine.drawObject(name)` can stop one object being drawn, `engine.on("drawGameBefore" / "drawGame")` draw behind and over the scene, and four `classic.*` tuning names open the damage rules of the older games.
- **Particle tuning.** `particle.amountScale`, `speedScale`, `lifeScale`, `sizeScale` and `gravityScale`; `clearParticleCache()` re-reads the particle table.
- **Everything changeable from Lua.** New global `engine` table: `engine.original` / `engine.resOriginal` (the engine's own natives, kept when a script replaces a global), `engine.natives()`, and `engine.on` / `off` / `emit` with the events `update`, `levelLoaded`, `objectCreated` and `objectRemoved`. `docs/SCRIPTING.md` has a new, complete native function reference and a chapter "Changing the engine from Lua".
- **`tuning` table and `contact` event.** The engine's built-in constants can be set from Lua (`tuning["sw.forceDivisor"] = 5`): Star Wars damage divisor, homing damage, hit wobble and sensor removal limit, Rio wobble, and the mouse-wheel zoom step and duration; and, in every game, the Box2D solver (iterations, slop, sleep time and tolerance), the Star Wars water formula, the revert-gravity strength, the hit-wobble curve, the flip speed and the `hasMovingObjects` thresholds. `engine.on("contact", function(a, b) ... end)` fires when two objects begin to touch. `docs/SCRIPTING.md` ends with a modding guide with pseudocode and recipes.
- **Asteroid-field rock layers (0x44adb0 / 0x44a800).** A layer with `spawnParameters` puts its rock on a random spot of its screen area, shifted by `(random - 0.5) * worldW / worldH` of the level box. The exe reads `amount` and `xSpeedVariance` but never uses them, so the engine ignores them too.
* **Release name.** `make_release.bat` writes `AngryBirdsEngine-v2.9.zip`.

The wrap shift is `scaleX * width * (1 + trunc((right - left) / (scaleX * width) * referenceScaleX))` and the same with the height (read from 0x44b200's code; before it used the on-screen size).
* **Foreground reference y (Star Wars NEW_THEME_SYSTEM):** the foreground layers (`fgLayers`) use the world y of the screen's top edge as their reference y every frame (0x44c1b0 overwrites ThemeSystem +0x20 for mode 0), so they take no vertical camera shift.

## New in 2.2.3

**Reading and changing the z of objects.** Everything about the `z_order` of blocks can now be asked for and changed from the scripts and the console (the rules of the draw order are under "Draw order and z"):

| Call | Meaning |
|---|---|
| `getObjectZOrder(name)` | the object's current `z_order`; `nil` if there is no such object (before: -1e9) |
| `objects.world[name].z_order` | the same value, from the table the scripts already read. It is kept up to date: `setObjectZOrder`, `bringObjectToFront`, `sendObjectToBack` and the console commands below write the new value into it |

## Changes since 2.1

Everything below was added after the 2.1 release and is part of 2.2. It is grouped by what it touches; the physics work is a comparison of the engine's functions with the Ghidra decompile of each retail exe.


### Lua compiler fix (constants beyond 256)
In a function with more than 256 constants, an expression such as `x + 800 * t.dir.x` was compiled so that the constant's register was overwritten by the second operand, giving `x + t.dir.x * t.dir.x`. The compiler now evaluates the second operand first (the same order later Lua versions use), for arithmetic and comparisons. Large scripts, such as a long game-logic file, now calculate these expressions correctly.

### Physics: Angry Birds 1.6.2 and the other Box2D 2.1 games (Classic, Seasons)

- Continuous collision follows the exe's own routine (the time of impact pass ported from 0x4e70d0): the earliest impact of all contacts that involve a static body is found, the bodies are moved there, the touching island is solved with the rest of the step and the pass repeats. `AB_OLDTOI=1` brings back the bundled Box2D routine, `AB_NOCCD=1` turns continuous collision off.
- `b2Contact::Update` checks the overlap of the two fixtures' boxes before it runs the narrow phase, as the exe does; the wake-up rules of `b2Body` and the term order of `Solve33` in `b2Math` match the exe.
- The island solver, the position solver's equalised mass and the TOI island follow the exe. Blocks are created awake, and every level load starts a brand new physics world (`AB_KEEPWORLD=1` restores the shared world). A restarted level now settles like the first load.
- Revolute and prismatic joints with both a motor and limits reverse at their limits by themselves (the Classic scripts never call `checkJointLimits`), which makes the Golden Eggs pickaxes move.
- The Eagle can be used once per level, as in the retail game.
- Seasons 1.0.0 to 2.2.0 use the same Box2D code as 1.6.2; the exes differ only in compiler inlining, so no separate physics is needed.

### Physics: Angry Birds Rio 1.4.2

Rio's exe contains a Box2D 2.2.0 trunk build with its own time of impact solver, which the engine now follows:

- `Island::SolveTOI` works on the earliest-impact contact, advances each body's sweep, and the "leap of faith" that commits the new positions applies to **every** body of the island, not only the two bodies of the contact.
- The group of bodies of a time of impact island stops growing at 32 bodies (`b2_maxTOIContacts`), the contact list has room for 4 times that.
- Contact partition, the sleep condition (it no longer depends on whether the position solver finished), the position solver's mass normalisation, its -1.5 x linear slop threshold and the TOI position solver (which moves both bodies) match the exe. Constants: linear slop 0.05, TOI target 0.15, tolerance 0.0125, 20 position iterations, Baumgarte 0.75.
- Rio instruction matching (v2.2): the position solver subtracts both radii in full (`b2_solverSkinFraction` = 1), the circle manifold returns the normal (1, 0) for coinciding centres, revolute and prismatic joints use the exe's 2.1-style Init / SolveVelocity / SolvePosition (including the large-detachment step), `b2Mat33::Solve33` uses the exe's term order, `b2Body::SetType` / `ResetMassData`, `AddPair` (no waking) and `Collide` (awake test) follow the exe, and the world is stepped with 10/10 iterations. Smuggler's Plane 1-10 still holds and 12-15 stays stable.

### Physics: how closely it follows the exes

The Box2D code of each game was compared, function by function, with the Ghidra decompile of that game's exe:

- **Angry Birds Rio 1.4.2** (`AngryBirdsRio.exe`, Box2D 2.2.0 trunk with 2.1-style joints): every Box2D function the engine uses was compared and made to follow the exe, including the order of the floating point terms. That covers the world step and solve, the time of impact pass, the contact manager (AddPair, Collide), the contact and position solvers and the polygon / circle manifolds, the island solve, the revolute, prismatic, weld and distance joints, bodies (SetType, mass data), the shapes' mass, centroid and ray casts, the GJK distance routine, and the dynamic tree and broadphase (the exe has the older 2.2.0 tree with a rebalance pass after each pair update, which decides the order contacts are created in).
- **Angry Birds 1.6.2** (Box2D 2.1.0): the world, the time of impact pass, the island and contact solvers, the joints and the collision functions follow the exe.
- **Angry Birds 2.0.0**: its decompile was compared with the 1.6.2 one. Of the Box2D functions, all but a few dozen are identical after the names are stripped, and the rest differ only in addresses, so 2.0.0 runs the same physics as 1.6.2.

What cannot be matched is the last bit of `sin`, `cos` and `sqrt`: the exes call the x87 versions, the engine uses the host's math library. Apart from that the physics in these games is the exes' physics. This was done by reading the decompiled code, not by comparing with recordings of the retail games, so a mistake in a function the engine does not run (or in a case no level reaches) would not have shown up.

### Drawing and speed

- **Static blocks that tile a texture draw correctly again.** A file used both as a sprite sheet image and as a repeating block texture is now kept as two textures (one that repeats, one that does not). When both wanted the same file, terrain showed as one flat colour.
- **Textures are uploaded when the sprite sheet is created**, behind the loading screen, like the exe does, instead of on the first draw. The frames after a menu or a level opened used to stutter, the more so the more sheets a game has.
- **A sprite name that is in no sheet is remembered**, like one that is. Before, every `drawSprite`, `getSpriteBounds` or `getSpritePivot` call with a name that does not exist walked every sprite of every sheet (about 40 microseconds in Rio, per call); scripts that measure or draw such names for each object each frame lost many milliseconds per frame. Composite sprite lookups are remembered too (a missing name now costs about 2.5 microseconds).
- **The hand cursor** (`CURSOR_*`) is now drawn at the very end of the frame, on top of everything the scripts and the engine draw (a background, a panel or the game drawn after the script's cursor call used to cover it, as in the Seasons editor), with the clip rectangle off and with z, blur, pixelation, transparency and tint of the sprites before it taken away. The system cursor is only hidden when a cursor sprite was really drawn that frame.

The empty stub was therefore correct (2.7 implements it for mods that pass the zoom; the game's own call still draws nothing). `drawForeground` (0x467330) only draws the foreground layer list, which no Space script fills. `setMenuParticlesScale` is only called for the iPhone 4 resolution switch. `createLineShape` is only used by the `STREAM_1` editor block.
- **Space background (`drawBackgroundNative`, 0x467f70)**: rewritten from the exe. Every layer (also the empty ones that only carry scattered elements) is placed with the camera snapshot taken at the first draw, the layer's `zDistance`, `scaleSpeed`, `xMult`, `yMult`, `angleMult` and `offsetX/offsetY`; looping layers are a row of copies, `createThemeSprite` elements are drawn on the layer index they name. Layers whose sprite is a composite (`THEME_1_BG_1` with its stars, `THEME_1_PARALLAX_3_LONG_VERSION_PC`) are drawn as composites; before, they were skipped, which left the flat blue screen.

- **Rio:** the bird pulled back in the slingshot no longer shows only its yell sprite; it blinks and squawks by the same timers as the waiting birds.
- **Rio and Space:** the trajectory dots, puffs and the aiming aid are drawn right before the first bird, so birds are in front of them (they used to be drawn over everything). The earlier games already drew them before the birds.
- **Space:** a level's own `gravityForceMultiplier` (1 in levels such as 1-19) is now used for the world; the engine always used the default of 4, so every planet pulled four times too hard in those levels (this was the gravity misread: the aim trail and the real flight bent down much too fast).
- **Space:** returning from an eggsteroid restores each object's radius, size and planet forces from the live level, which fixes the `radius` (a nil value) crash when the level draws again.
- **Space:** the aim trail now honours a planet's gravity filter (`gravityCollisionMask` against the bird's category), as the exe's gravity function does; `saveLevelForReload` really saves the level, which fixes the crash when entering an eggsteroid.
